Projet & sauvegarde

Les fichiers d'un projet AngeVault (.angproj, .scene, .prefab, .map, .tileset), comment ils sont écrits et comment le module scene les lit.

Un projet = des fichiers JSON

Depuis le module scene, tout ce que l'on construit dans l'éditeur s'enregistre dans des fichiers texte JSON, lisibles et faciles à versionner avec Git. Le même code les lit dans l'éditeur (F5) et dans rpg.exe.

ExtensionFormat (format)ContientExemple
.angprojangeVault.projectLe projet : scène de départ, liste des scènes, dossiers, fenêtre, systèmes actifsrpg.angproj
.sceneangeVault.sceneDes entités et leurs composantsscenes/main.scene
.prefabangeVault.prefabUn groupe d'entités réutilisableprefab/Player.prefab
.mapangeVault.tilemapUne carte : taille, orientation, cases (voir Tilemaps & tilesets)maps/iso_demo.map
.tilesetangeVault.tilesetUne feuille d'images découpée en tilesassets/tilesets/demo/herbe.tileset
input.cfgtexteLes actions de l'Input Manager (voir Input)assets/input.cfg

Tous les chemins écrits dans ces fichiers sont relatifs au dossier du .angproj : un projet se copie ou se déplace sans rien casser.

Le fichier projet .angproj

projects/rpg/rpg.angprojJSON
{
  "format": "angeVault.project",
  "version": 1,
  "name": "RPG",
  "startScene": "scenes/main.scene",
  "scenes": [ "scenes/main.scene", "scenes/iso_demo.scene" ],
  "paths":  { "assets": "assets", "input": "assets/input.cfg", "settings": "assets/settings.cfg" },
  "window": { "title": "RPG", "size": [1920, 1080] },
  "systems": { "ForceDebugSystem": false }
}
CléRôle
startSceneLa scène chargée à l'ouverture du projet et par rpg.exe
scenesLes scènes du projet (Enregistrer sous… ajoute la nouvelle scène à cette liste)
pathsDossier des assets, fichier des actions d'entrée (input) et fichier des paramètres du jeu (settings)
windowTitre et taille de la fenêtre du jeu. La vsync, le plein écran, l'antialiasing, la limite de FPS et le shader ne sont plus ici : ils sont dans assets/settings.cfg (voir plus bas)
systemsSystèmes désactivés : nom de la classe → true / false. Un système absent de la liste est actif. Modifié par Exécuter → Systèmes…

La classe Project (scene/project.h) offre load, save, directory(), resolve(chemin) (relatif → complet), relative(chemin) (l'inverse), addScene et Project::create(dossier, nom, projet), qui crée nom.angproj, assets/, scenes/ et une scène vide.

Le fichier scène .scene

Une scène est une liste d'entités. Chaque entité a un id et une table de composants, un objet JSON par composant.

scenes/main.scene (abrégé)JSON
{
  "format": "angeVault.scene",
  "version": 1,
  "name": "main",
  "map": null,
  "entities": [
    {
      "id": 18092514487157541069,
      "components": {
        "Name":        { "name": "Player" },
        "Transform2D": { "position": [-395.7, 637.0], "rotation": 0.0, "scale": [1.0, 1.15], "depth": 0.0 },
        "Geometry":    { "layer": 1, "shape": "Sprite", "texture": "player", "rect": [0, 0, 32, 64], "tint": "#FFFFFFFF" },
        "RigidBody2D": { "mass": 1.0, "linearDrag": 0.05, "friction": 0.4 },
        "Collider2D":  { "offset": [0, 22], "shape": "Box", "halfSize": [16, 15], "isTrigger": false },
        "Script":      { "behaviors": [ { "name": "PlayerBehavior", "properties": { "speed": 400.0 } } ] }
      }
    },
    {
      "id": 901886561833534410,
      "components": {
        "Name": { "name": "CameraEntity" },
        "Camera2d":     { "zoom": 1.0, "minZoom": 0.25, "maxZoom": 4.0, "rotation": 0.0,
                          "priority": 0, "active": true, "blendTime": 0.0 },
        "CameraFollow": { "target": 18092514487157541069, "smoothTime": 0.15, "lookAhead": 0.0 },
        "CameraBounds": { "min": [-1000, -1000], "max": [3000, 3000], "limitZoom": true }
      }
    }
  ],
  "editor": { "categories": ["Personnages"], "entityCategory": { "18092514487157541069": "Personnages" } }
}
  • Composants connus : Name, Transform2D, Geometry, RigidBody2D, Collider2D, Camera2d, CameraFollow, CameraBounds, CameraControl, CameraShake, Tilemap, Script, plus les composants de jeu déclarés avec REGISTER_COMPONENT (voir Code de jeu).
  • Couleurs : texte "#RRGGBBAA". Vecteurs et rectangles : tableaux de nombres.
  • Script : un composant qui porte une liste de comportements. Chacun est enregistré par son nom de classe et la valeur de ses champs PROPERTY. Au chargement, la fabrique (BehaviorFactory) recrée le bon objet à partir du nom. Un nom inconnu (classe renommée ou supprimée) donne un avertissement, sans bloquer le chargement.
  • Tilemap : seulement le chemin du .map et l'indicateur visible ; les cases sont dans le fichier .map.
  • editor : réservé à l'éditeur (catégories de la Hierarchy). Le jeu l'ignore.
  • Composant inconnu : il est ignoré avec un avertissement. Le fichier reste donc lisible par une version plus ancienne du moteur.

PersistentId : des liens qui survivent à l'enregistrement

Une Entity est un index mémoire (avec sa génération) : il change à chaque chargement. Pour relier des entités dans un fichier, chacune reçoit un PersistentId, un entier de 64 bits tiré au hasard (jamais 0) qu'elle garde ensuite pour toujours : ensurePersistentIds en donne un à chaque entité qui n'en a pas avant l'écriture. Les entités créées en cours de partie (balles, particules) n'en ont pas besoin. Un lien est écrit avec cet identifiant : par exemple Camera2d::targetLock pointe vers le joueur par son id.

Le chargement se fait donc en deux passes :

  1. créer toutes les entités (chacune avec son PersistentId) ;
  2. lire les composants ; un lien est converti de PersistentId vers l'Entity créée à la passe 1 (LoadContext::entityOf).

Si la cible d'un lien n'existe pas (entité absente du fichier ou d'un prefab), le lien devient NULL_ENTITY et un avertissement est ajouté à SceneLoadResult::warnings. C'est ce que vérifie le test test_scene (aller-retour : enregistrer, recharger, comparer).

Lire et écrire en C++

scene/scene_io.hC++
SceneMeta meta;                                             // nom, map associée, données de l'éditeur

// Le jeu : charger
SceneLoadResult r = loadScene(game.registry(), meta, project.resolve(project.startScene));
if (!r.ok) std::cerr << r.error << "\n";
for (const std::string& w : r.warnings) std::cerr << "[Scène] " << w << "\n";

// L'éditeur : enregistrer (Ctrl+S)
std::string error;
saveScene(registry, meta, "scenes/main.scene", &error);

// Sans fichier : une scène dans une chaîne (le mode Jouer en fait une copie)
std::string json = sceneToString(registry, meta);
sceneFromString(otherRegistry, meta, json);
FonctionRôle
saveScene / loadSceneÉcrire / lire un fichier. L'écriture est atomique (writeFileAtomic : fichier .tmp puis renommage) : une panne en plein enregistrement ne détruit pas l'ancienne version
sceneToString / sceneFromString, sceneToJson / sceneFromJsonMêmes opérations sur une chaîne ou un objet JSON
ensurePersistentIdsDonne un identifiant à chaque entité qui n'en a pas (appelé avant d'écrire)
entitiesToJson / entitiesFromJson(…, freshIds)Le cœur commun aux scènes et aux prefabs. freshIds = true donne de nouveaux identifiants (copie), en gardant les liens internes
clearRegistryDétruit toutes les entités tout de suite (à faire avant de charger une autre scène : le chargement ajoute au registre)
loadTilemaps(registry, dossierProjet, warnings)Après le chargement : lit les fichiers .map des composants Tilemap qui n'ont pas encore leurs données

Sérialiseurs de composants

Chaque composant sait s'écrire grâce à un sérialiseur enregistré dans le SerializerRegistry. Les composants du moteur ont les leurs ; ceux du jeu sont ajoutés automatiquement. Pour un composant à part, on enregistre ses fonctions de sauvegarde et de chargement :

scene/component_serializer.hC++
SerializerRegistry::get().add<Health>("Health",
    // sauvegarde : composant -> JSON
    [](Health& h, const SaveContext&) {
        return Json{ { "hp", h.hp }, { "max", h.max } };
    },
    // chargement : JSON -> composant (créé avec Health{} avant : valeurs absentes = défauts)
    [](Health& h, const Json& j, const LoadContext&) {
        h.hp  = j.value("hp", h.hp);
        h.max = j.value("max", h.max);
    });
  • addReflected<T>(nom) : pour un composant déclaré avec REGISTER_COMPONENT : ses champs FIELD sont lus et écrits seuls.
  • SaveContext::idOf(entité) et LoadContext::entityOf(id) convertissent les liens ; LoadContext::warn(texte) ajoute un avertissement.
  • Le namespace SceneJson offre des aides : vecteurs, rectangles, couleurs "#RRGGBBAA", lecture des PROPERTY des comportements.

Prefabs

Un prefab est une scène en miniature : une liste d'entités (avec leurs liens internes) enregistrée dans un fichier .prefab. Dans l'éditeur, on le crée en glissant une entité de la Hierarchy vers le panneau Project (une caméra qui suit l'entité est incluse), et on l'instancie en le glissant dans la vue scène.

scene/prefab.hC++
// Créer : l'entité racine (la première) + les caméras qui la suivent
savePrefab(registry, prefabGroup(registry, player), "Player", "prefabs/Player.prefab", &error);

// Instancier : de NOUVEAUX PersistentId, liens internes conservés
SceneLoadResult r = instantiatePrefabFile(registry, "prefabs/Enemy.prefab",
                                          sf::Vector2f{ 400.f, 300.f });   // position facultative
if (r.ok) Entity enemy = r.entities.front();                                 // la racine

Sans position, l'instance apparaît là où le prefab a été créé ; avec une position, la racine y est placée et les autres entités gardent leur décalage. prefabGroup calcule le groupe à enregistrer à partir d'une entité racine. Le résultat de instantiatePrefabFile peut être appelé depuis un comportement pour faire apparaître un ennemi en cours de partie.

Ouvrir un projet : ce que fait rpg.exe

projects/rpg/main.cpp (résumé)C++
// rpg.exe [projet.angproj] [scene.scene]
Project project;
project.load(projectPath);                                      // 1. le projet
settings.loadFromFile(project.resolve(project.settingsPath));    // 2. les paramètres du jeu (settings.cfg)
Game game({ w.width, w.height }, w.title, settings);            //    la fenêtre réglée par le projet
registerRpgSystems(game);                                       //    Physics, Collision, Script, systèmes caméra
game.applySystemSettings(project.systems);                      // 3. systèmes désactivés
loadRpgInput(game.input(), project.resolve(project.inputPath)); // 4. les touches (input.cfg)
loadScene(game.registry(), meta, scenePath);                    // 5. la scène
loadTilemaps(game.registry(), project.directory(), &warnings);  // 6. les cartes (.map)
game.run();

Sans argument, rpg.exe cherche rpg.angproj à côté de lui (CMake l'y copie, avec le dossier scenes/) et joue sa scène de départ. Avec deux arguments (rpg.exe projet.angproj scene.scene), il joue la scène donnée : c'est ce que fait Ctrl+F5 dans l'éditeur, après avoir enregistré la scène. Les avertissements de chargement (composant inconnu, carte introuvable…) sont écrits sur la sortie d'erreur. S'il n'y a ni projet ni scène lisible, il retombe sur la scène écrite en code (loadRpgEntities de rpg_scene.h), conservée comme solution de secours.

Paramètres du jeu : settings.cfg

Les réglages d'affichage ne sont pas dans le .angproj mais dans un petit fichier texte, assets/settings.cfg (chemin : paths.settings). Fichier absent ou clé manquante : valeurs par défaut. Il se modifie à la main ou par Édition → Paramètres du jeu….

assets/settings.cfgShell
fullscreen = false
vsync = true
antialiasing = 4            # 0, 2, 4, 8 ou 16
fpsLimit = 0                # 0 = illimité, ignoré si vsync
shader = assets/shaders/postprocess.frag
shader.contrast = 1.1       # réglage déclaré par « // @param » dans le shader

Le shader est un fichier .frag relatif au projet, appliqué à l'image du jeu avant son affichage (il reçoit frame, resolution et time). Chaque réglage est déclaré dans le shader par uniform float contrast; // @param 1.0 0.0 2.0 (défaut, minimum, maximum) et enregistré sous la clé shader.contrast. Si le shader est introuvable ou ne compile pas, il est ignoré et un message s'affiche.

Dans l'éditeur

ActionRaccourciCe qui se passe
Fichier → Nouveau projet…Demande un dossier puis un nom, appelle Project::create (.angproj, assets/, scenes/, scène vide) et l'ouvre
Fichier → Ouvrir…Ctrl+OUn .angproj (avec sa scène de départ) ou un .scene
Fichier → RécentsLes derniers projets. L'éditeur rouvre le dernier projet au démarrage (sinon le RPG)
Fichier → Nouvelle scèneCtrl+NUne scène vide, sans chemin
Fichier → EnregistrerCtrl+SsaveScene ; sur une scène neuve (sans chemin), ouvre « Enregistrer sous… »
Fichier → Enregistrer sous…Ctrl+Maj+SPropose le dossier scenes/ du projet, écrit le fichier et ajoute la scène au .angproj

Un astérisque dans le titre de la fenêtre signale des modifications non enregistrées, et l'éditeur pose la question en quittant. Le mode Jouer (F5) charge une copie de la scène (sceneSnapshot) : ce qui bouge pendant le jeu ne modifie jamais la scène éditée. Voir le guide de l'éditeur.

Sandbox. Le projet Sandbox ne passe pas encore par ces fichiers : sa scène est toujours écrite en code (loadSandboxScene). Seul le projet RPG (et le projet vide projects/test/test.angproj) utilise .angproj et .scene.
