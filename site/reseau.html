Réseau & HTTPS

Le client HTTP/HTTPS asynchrone prévu pour AngeVault : conception, prototype commenté et façon de l'intégrer à l'ECS.

Statut : module prévu. Le dépôt actuel ne contient pas encore de dossier engine/net, et cmake/Dependencies.cmake désactive le réseau de SFML (SFML_BUILD_NETWORK OFF), qui ne gère pas HTTPS. Cette page décrit la conception visée et un prototype ; ce n'est pas du code déjà livré.

Objectif

Permettre à un jeu de dialoguer avec un serveur distant (classements, sauvegardes en ligne, mises à jour, authentification) en HTTPS, avec des réponses JSON, sans jamais bloquer la boucle de jeu.

  • libcurl pour le transport (HTTPS via un backend TLS : OpenSSL ou Schannel selon la plateforme).
  • std::async / std::future pour l'asynchronisme : la requête part sur un autre thread, le jeu consulte le résultat quand il est prêt.
  • nlohmann_json pour lire les réponses (déjà prévu comme dépendance du futur module scene).

Prototype du client

La première ébauche passait directement un CURL* sans récupérer le corps de la réponse. La version ci-dessous ajoute ce qui manque pour qu'elle fonctionne : une fonction d'écriture, le code HTTP, un délai maximal et la libération des ressources.

engine/net/include/http_client.h (prototype)C++
#pragma once
#include <string>
#include <future>
#include <curl/curl.h>

namespace AngeVault {

struct HttpResponse {
    int         statusCode = 0;
    std::string body;
    std::string error;      // message libcurl si success == false
    bool        success = false;
};

class HttpClient {
public:
    // À appeler une fois au démarrage du programme, et curl_global_cleanup() à la fin.
    static void init()     { curl_global_init(CURL_GLOBAL_DEFAULT); }
    static void shutdown() { curl_global_cleanup(); }

    static std::future<HttpResponse> getAsync(const std::string& url, long timeoutSeconds = 10) {
        return std::async(std::launch::async, [url, timeoutSeconds]() {
            HttpResponse res;
            CURL* curl = curl_easy_init();
            if (!curl) { res.error = "curl_easy_init a echoue"; return res; }

            curl_easy_setopt(curl, CURLOPT_URL, url.c_str());
            curl_easy_setopt(curl, CURLOPT_WRITEFUNCTION, &HttpClient::onWrite);
            curl_easy_setopt(curl, CURLOPT_WRITEDATA, &res.body);
            curl_easy_setopt(curl, CURLOPT_FOLLOWLOCATION, 1L);
            curl_easy_setopt(curl, CURLOPT_TIMEOUT, timeoutSeconds);
            curl_easy_setopt(curl, CURLOPT_SSL_VERIFYPEER, 1L);   // ne jamais désactiver
            curl_easy_setopt(curl, CURLOPT_SSL_VERIFYHOST, 2L);

            CURLcode code = curl_easy_perform(curl);
            res.success = (code == CURLE_OK);
            if (res.success)
                curl_easy_getinfo(curl, CURLINFO_RESPONSE_CODE, &res.statusCode);
            else
                res.error = curl_easy_strerror(code);

            curl_easy_cleanup(curl);
            return res;
        });
    }

private:
    static size_t onWrite(char* data, size_t size, size_t count, void* userdata) {
        static_cast<std::string*>(userdata)->append(data, size * count);
        return size * count;
    }
};

} // namespace AngeVault
ChangementPourquoi
CURLOPT_WRITEFUNCTION + WRITEDATASans elles, libcurl écrit la réponse sur la sortie standard : body reste vide.
CURLINFO_RESPONSE_CODERemplit statusCode, que le prototype initial laissait à 0.
curl_global_init / cleanuplibcurl demande une initialisation globale avant tout thread ; on la fait une fois, au démarrage.
CURLOPT_TIMEOUTUn serveur muet ne doit pas garder un thread indéfiniment.
errorDistingue « le serveur a répondu 404 » (success == true, statusCode == 404) de « la connexion a échoué ».

Utilisation sans bloquer le jeu

Ne jamais appeler future.get() directement dans onUpdate : cela bloquerait la frame. On garde le future et on teste s'il est prêt, chaque frame, sans attendre.

behaviors/leaderboard.h (exemple)C++
class LeaderboardBehavior : public IBehavior {
public:
    void onStart(Entity self, Registry& registry) override {
        m_pending = AngeVault::HttpClient::getAsync("https://example.com/api/scores");
    }

    void onUpdate(Entity self, Registry& registry, float dt) override {
        if (!m_pending.valid()) return;

        // wait_for(0) : on ne bloque pas, on regarde seulement si c'est prêt
        if (m_pending.wait_for(std::chrono::seconds(0)) == std::future_status::ready) {
            AngeVault::HttpResponse res = m_pending.get();
            if (res.success && res.statusCode == 200) {
                // parser res.body (JSON) et mettre à jour des composants
            }
        }
    }

private:
    std::future<AngeVault::HttpResponse> m_pending;
};

Pour plusieurs requêtes à la fois, un composant PendingRequest { std::future<HttpResponse> … } et un NetSystem qui parcourt ces composants avec registry.view évitent de répéter ce schéma dans chaque comportement.

Sécurité

  • Laissez la vérification TLS activée (VERIFYPEER = 1, VERIFYHOST = 2). Désactiver la vérification « pour que ça marche » rend la connexion vulnérable.
  • Selon le backend TLS choisi (OpenSSL notamment), il faut fournir un bundle de certificats d'autorité (CURLOPT_CAINFO) ou utiliser le magasin du système.
  • N'enregistrez jamais de secret (clé d'API, jeton) dans le dépôt ni dans les assets distribués avec le jeu.
  • Traitez toute réponse comme non fiable : validez le JSON avant de modifier des composants.

Étapes pour le créer

  1. Choisir comment obtenir libcurl (FetchContent, vcpkg…) et l'ajouter à cmake/Dependencies.cmake.
  2. Créer engine/net/ avec av_module(Net DEPS …) et l'ajouter à engine/CMakeLists.txt (voir la recette).
  3. Placer http_client.h dans engine/net/include/.
  4. Ajouter AngeVault::Net à la cible av_engine.
  5. Écrire un test avec un serveur local (par exemple une réponse JSON statique) avant de viser un serveur distant.
