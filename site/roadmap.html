Points d'attention repérés dans le code

Constats faits dans la copie locale du dépôt, relus le 10/11/2026. #4 (« traiter les points d'attention ») est terminée : plusieurs points ont d'ailleurs été corrigés depuis (tri des systèmes devenu stable, caméra branchée sur l'Input Manager, chemin du input.cfg donné par le projet, fonction test vide de render_system.h supprimée, actions de caméra désormais lues par CameraControl).

#OùConstatPisteLien
1tests/test_tilemap.cppLe test utilise encore l'ancienne interface des cartes (m.tile(2), removeTile, cases "40*1") qui n'existe plus dans tilemap.h : il ne devrait plus compiler, et AV_BUILD_TESTS est à ON par défaut.Réécrire le test pour TileCell, addTileset / removeTileset et le format .map version 2, ou le retirer de tests/CMakeLists.txt en attendant.#55
2Game::init()m_systems.start() n'est appelé qu'à la construction : les systèmes ajoutés ensuite (Physics, Collision, Script et les systèmes caméra via registerRpgSystems) ne reçoivent jamais onStart. Les systèmes REGISTER_SYSTEM, eux, sont ajoutés avant le démarrage.Appeler onStart dans add si le jeu est déjà démarré, ou exposer un game.start() après le chargement de la scène.#24
3ScriptSystemonDestroy n'est appelé qu'à l'arrêt du jeu, pas à la destruction d'une entité isolée.Brancher Registry::onDestroy<Script> pour appeler onDestroy.—
4Game / LooseFileLoaderLe chargeur est construit avec son chemin par défaut games/rts/assets/resources.txt, hérité du prototype RTS. Sans ce fichier, les identifiants de texture sont traités comme des chemins directs ; un message « loading path from » s'affiche à chaque lancement.Passer un chemin explicite (dossier assets du projet).#38
5engine/ai/CMakeLists.txtContient av_module(Core …) : le nom devrait être AI (sans effet tant que le dossier n'est pas ajouté à engine/CMakeLists.txt).Renommer avant d'activer le module.#45
6registerCameraSystemsLes cinq systèmes caméra ne sont pas ajoutés par Game::init() : seul un projet qui appelle registerCameraSystems (le RPG, via registerRpgSystems) a une caméra. Un nouveau projet sans cet appel n'affiche rien d'autre que la vue par défaut. Comme les autres systèmes ajoutés après le constructeur, ils ne reçoivent pas onStart.Documenté (voir Créer un système) ; à terme, enregistrer la caméra dans Game::init().—
7Intégration continueAucun dossier .github/ dans la copie lue : pas de build ni de test automatique.Ajouter un workflow qui lance le preset x64-debug-no-editor puis ctest (il aurait signalé le point 1).#1
8SandboxLe Sandbox n'utilise ni l'Input Manager (il lit sf::Keyboard) ni les fichiers de scène.Le migrer vers un .angproj, ou le déclarer figé.—
9Code de jeuLe code de jeu est lié à l'éditeur : après chaque changement de C++, il faut recompiler l'éditeur. Pas de rechargement à chaud, et un seul projet (le RPG) a son code lié.Pour d'autres projets, répéter le schéma de projects/rpg/CMakeLists.txt (liste des trois dossiers).#32
10TestsSont couverts : ComponentPool, maths, sauvegarde (test_scene), systèmes caméra (test_camera). Rien pour Registry::view, la destruction différée, les collisions, l'InputManager (lecture de input.cfg) ni les tilesets / l'autotile.Ajouter ces tests.#55
