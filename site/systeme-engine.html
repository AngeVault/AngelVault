Créer un système (côté engine)

Écrire un système dans le moteur lui-même (dossier engine/), le brancher à la boucle de jeu, le rendre activable depuis l'éditeur et le tester. À ne pas confondre avec un système de jeu, qui vit dans un projet.

Moteur ou projet ?

Un système est une classe qui hérite de ISystem et qui parcourt des composants à chaque frame. Il peut vivre à deux endroits, et la bonne réponse dépend de qui s'en sert :

Système de jeu (projet)Système du moteur (engine/)
Oùprojects/rpg/systems/engine/<module>/include/systems/
Pour quiun seul jeutous les jeux et l'éditeur
BranchementREGISTER_SYSTEM(MonSysteme) : automatiqueà la main : Game::init() ou une fonction registerXxxSystems
Dépendancestout le moteurseulement celles du module (voir le graphe de dépendances de la Vue d'ensemble et les Modules du moteur)
GuideCode de jeucette page

Règle simple : si la règle est propre à votre jeu (un ennemi qui poursuit le joueur), elle va dans le projet. Si elle est générale (la physique, le rendu, le tremblement de caméra), elle va dans le moteur, avec son composant (voir Créer un composant (côté engine)).

Les exemples de cette page construisent un système fictif, LifetimeSystem : il détruit les entités dont le composant Lifetime arrive à zéro (étincelles, projectiles…). Les vrais systèmes cités en comparaison (CameraShakeSystem, PhysicsSystem) sont ceux du dépôt.

Ce que fournit ISystem

engine/core/include/ecs/system.hC++
struct ISystem {
    virtual ~ISystem() = default;
    virtual void onStart(Registry& registry) {}
    virtual void onUpdate(Registry& registry, float dt) = 0;   // obligatoire
    virtual void onStop(Registry& registry) {}

    int priority = 0;       // ordre d'exécution : le plus petit d'abord
    bool enabled = true;    // faux : onUpdate n'est plus appelé
    std::string name;       // rempli par SystemManager (nom de la classe)
};

onStartune fois, à m_systems.start()facultatif ; voir l'avertissement plus bas
onUpdatechaque frame, si enableddt en secondes ; c'est là que vit la logique
onStopà Game::stop()libérer ce que onStart a pris
priorityau moment de l'ajoutse règle dans le constructeur (priority = 6;) ; tri stable : à priorité égale, l'ordre d'ajout
nameà l'ajoutnom de la classe, utilisé par setEnabled, le .angproj et Exécuter > Systèmes…

Étape 1 : choisir le module

Un système se range dans le module qui possède ses données et ses dépendances. Le module est un dossier engine/<nom>/ avec un include/ (en-têtes publics) et, facultativement, un src/ :

Votre système…ModuleExemple existant
ne dépend que de l'ECS, des transformations ou des scriptsCoresystems/script_system.h
touche aux corps rigides ou aux collisionsPhysics2DPhysicsSystem, CollisionSystem
dessine, ou règle la vueRender2DRenderSystem, CameraShakeSystem
gère des particulesParticlesParticleSystem

Core ne dessine pas. Core ne dépend que de SFML::System et de glm : pas de sf::RenderTarget, pas de texture. Un système qui dessine doit aller dans Render2D (seul module qui dessine). Respectez le sens des dépendances : un module ne doit jamais inclure un module « au-dessus » de lui.

Si aucun module ne convient, créez-en un (dossier, CMakeLists.txt, add_subdirectory) :

engine/monmodule/CMakeLists.txtCMake
# Un module = un dossier = une cible AngeVault::<Nom>
# 100 % en-têtes (pas de src/*.cpp) : cible INTERFACE ; avec des .cpp : bibliothèque statique
av_module(MonModule DEPS AngeVault::Core AngeVault::Physics2D)
engine/CMakeLists.txtCMake
add_subdirectory(monmodule)   # ajoutez la ligne avec les autres modules

add_library(av_engine INTERFACE)
add_library(AngeVault::Engine ALIAS av_engine)
target_link_libraries(av_engine INTERFACE
    AngeVault::Core AngeVault::Physics2D AngeVault::Particles AngeVault::Tilemap
    AngeVault::Render2D AngeVault::Runtime AngeVault::Input AngeVault::Scene
    AngeVault::MonModule)       # ... et ajoutez la cible ici

av_module (défini dans cmake/AngeVaultHelpers.cmake) fait le reste : il compile tous les src/**/*.cpp, expose include/ et impose C++20. Les modules prévus mais pas encore créés (assets, animation, audio, ui, ai) suivront ce même modèle.

Étape 2 : écrire le système

Le composant d'abord (voir la page suivante), puis le système. Un fichier d'en-tête par système, dans include/systems/ :

engine/core/include/systems/lifetime_system.hC++
#pragma once
// Détruit les entités dont la durée de vie (Lifetime) est écoulée.
#include "ecs/system.h"
#include "ecs/registry.h"
#include "components/lifetime.h"

class LifetimeSystem : public ISystem {
public:
    LifetimeSystem() { priority = 9; }   // après la logique, avant le rendu (Render = 10)

    void onUpdate(Registry& registry, float dt) override {
        registry.view<Lifetime>([&](Entity e, Lifetime& life) {
            life.remaining -= dt;
            if (life.remaining <= 0.f)
                registry.destroyEntity(e);   // différé : voir l'encadré
        });
    }
};

Les règles à respecter dans onUpdate :

  • Parcourir avec registry.view<A, B>(…) : la lambda reçoit l'entité puis une référence à chaque composant demandé. Seules les entités qui possèdent tous les composants sont visitées.
  • Détruire avec registry.destroyEntity(e) : la destruction est différée. L'entité reste valide jusqu'à la fin de la frame (Game::tick appelle flushPendingDestroys() après tous les systèmes), donc le rendu la dessine encore une dernière fois.
  • Ne pas ajouter ou retirer de composant pendant un view sur ce même type de composant : la liste parcourue changerait sous vos pieds. Collectez les entités concernées, puis modifiez après la boucle.
  • Entités liées (CameraFollow::target) : vérifiez toujours registry.isValid(target) avant de l'utiliser, la cible peut avoir été détruite (voir CameraFollowSystem).
  • Pas d'état partagé caché : mettez les données dans les composants (elles sont sauvegardées avec la scène) et gardez dans le système seulement ce qui est temporaire.

Choisir la priorité

La priorité est l'ordre d'exécution dans la frame. Voici où se placent les systèmes actuels ; choisissez la vôtre par rapport à ce dont votre système dépend :

PrioritéSystèmePrioritéSystème
−1CameraControlSystem6CameraShakeSystem
0PhysicsSystem7CameraSystem
1CollisionSystem8TilemapRenderSystem
2ScriptSystem10RenderSystem
3ParticleSystem11RenderCollisionSystem
4CameraFollowSystem12ForceDebugSystem
5CameraBoundsSystem
  • Il lit des positions finales ? Après la physique et les scripts (≥ 3).
  • Il modifie la vue ? Avant CameraSystem (7), qui l'applique à l'image.
  • Il dessine ? Après la caméra et la carte, vers 10 et au-delà (RenderSystem trie lui-même par couche).
  • Deux systèmes de même priorité : ordre d'ajout. Si l'ordre compte, changez la priorité plutôt que de compter sur l'ordre d'ajout.

Étape 3 : le brancher

Écrire la classe ne suffit pas : aucun système du moteur n'est ajouté tout seul. Deux façons de le brancher :

A. Dans Game::init() : toujours actif

Pour un système que tout jeu doit avoir (comme le rendu). Dans engine/runtime/src/game_loop.cpp :

engine/runtime/src/game_loop.cppC++
#include "systems/lifetime_system.h"     // en haut du fichier

void Game::init() {
    InputManager::setCurrent(&m_input);
    syncScene();
    m_systems.addSystem<LifetimeSystem>();                                // <- votre système
    m_systems.addSystem<TilemapRenderSystem>(m_scene, m_textureLoader);
    m_systems.addSystem<RenderSystem>(m_scene, m_textureLoader);
    // ...
    for (const GameSystemInfo& info : GameSystemRegistry::get().all()) m_systems.add(info.create(*this, m_scene));
    m_systems.start(m_registry);        // onStart de tous les systèmes ajoutés jusqu'ici
}

Les arguments passés à addSystem<T>(args…) vont au constructeur : m_scene (l'image du jeu, sf::RenderTarget) pour un système qui dessine ou qui a besoin de la taille de l'écran.

B. Une fonction registerXxxSystems : le projet choisit

Pour des systèmes optionnels ou groupés, comme la caméra : une fonction inline qui ajoute tout le groupe dans le bon ordre, et que chaque projet appelle.

engine/render2d/include/systems/camera_systems.hC++
inline void registerCameraSystems(SystemManager& systems, sf::RenderTarget& target) {
    systems.addSystem<CameraControlSystem>();
    systems.addSystem<CameraFollowSystem>();
    systems.addSystem<CameraBoundsSystem>(target);
    systems.addSystem<CameraShakeSystem>();
    systems.addSystem<CameraSystem>(target);
}
projects/rpg/rpg_scene.hC++
inline void registerRpgSystems(Game& game) {
    game.systems().addSystem<PhysicsSystem>();
    game.systems().addSystem<CollisionSystem>();
    game.systems().addSystem<ScriptSystem>();
    registerCameraSystems(game.systems(), game.target());   // <- le projet appelle le groupe
}
ChoixAvantageLimite
A : Game::init()tous les projets et l'éditeur l'ont, onStart est appelémodifie le runtime ; Runtime doit pouvoir inclure le module
B : registerXxxSystemschaque projet décide, un seul appel pour un groupeun projet qui oublie l'appel n'aura pas le système ; pas d'onStart

À savoir sur onStart. Game::init() appelle m_systems.start() une seule fois, dans le constructeur de Game. Un système ajouté plus tard (cas B, registerRpgSystems) ne reçoit jamais onStart : faites son initialisation dans le constructeur, ou au premier onUpdate. onStop est en revanche appelé pour tous.

Étape 4 : l'activer ou le couper par son nom

Le SystemManager connaît chaque système par son name (le nom de la classe, rempli par addSystem). Il n'y a rien d'autre à écrire pour que votre système apparaisse dans l'éditeur, sous Exécuter > Systèmes…, et dans le projet :

projects/rpg/rpg.angprojJSON
{
  "systems": {
    "ForceDebugSystem": false,
    "LifetimeSystem": true
  }
}

Depuis le code : game.systems().setEnabled("LifetimeSystem", false) (renvoie false si le nom est inconnu), isEnabled(name), find(name), list(). Game::applySystemSettings applique la table du .angproj en ignorant les noms inconnus.

Ne renommez pas une classe à la légère. Le nom est la clé dans le .angproj : renommer LifetimeSystem fait perdre son réglage dans les projets existants (le nom inconnu est simplement ignoré).

Étape 5 : le tester

Un système n'a besoin ni de fenêtre ni d'éditeur : il suffit d'un Registry et d'appeler onUpdate. Les tests sont des exécutables simples (pas de framework) listés dans tests/CMakeLists.txt :

tests/test_lifetime.cppC++
#include "components/lifetime.h"
#include "systems/lifetime_system.h"
#include <cstdio>

static int g_failures = 0;
#define CHECK(cond) do { if (!(cond)) { std::printf("ECHEC ligne %d : %s\n", __LINE__, #cond); ++g_failures; } } while (0)

int main() {
    Registry r;
    const Entity e = r.createEntity();
    r.addComponent<Lifetime>(e).remaining = 1.f;

    LifetimeSystem sys;
    sys.onUpdate(r, 0.5f);
    CHECK(r.isValid(e));                 // pas encore écoulée

    sys.onUpdate(r, 0.6f);
    r.flushPendingDestroys();            // la destruction est différée : on la valide à la main
    CHECK(!r.isValid(e));

    return g_failures == 0 ? 0 : 1;
}
tests/CMakeLists.txtCMake
add_executable(test_lifetime test_lifetime.cpp)
target_link_libraries(test_lifetime PRIVATE AngeVault::Core)   # le module qui contient le système
add_test(NAME test_lifetime COMMAND test_lifetime)

Lancez-les avec ctest --test-dir build --output-on-failure. Pour un exemple réel, voir tests/test_camera.cpp : il teste CameraFollowSystem, CameraShakeSystem et CameraControlSystem sans fenêtre (seuls CameraSystem et CameraBoundsSystem ont besoin d'une cible de rendu). Concevez vos systèmes pour que leur logique soit testable ainsi : la cible de rendu ne doit être demandée que par ceux qui dessinent vraiment.

Liste de contrôle

  • □ Le module choisi a les dépendances nécessaires (av_module(… DEPS …)) et n'inclut rien « au-dessus » de lui.
  • □ include/systems/mon_systeme.h : #pragma once, classe qui hérite de ISystem, priority réglée dans le constructeur.
  • □ Le composant existe, est sérialisé et visible dans l'Inspector (page suivante).
  • □ Branché : Game::init() (A) ou registerXxxSystems appelé par le projet (B).
  • □ Initialisation dans le constructeur si le système est ajouté après Game::init().
  • □ Test dans tests/ + add_test.
  • □ Le système apparaît dans Exécuter > Systèmes… et se coupe sans planter.
  • □ Documenté : priorité ajoutée au tableau de la page Vue d'ensemble.
