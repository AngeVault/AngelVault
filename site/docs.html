Créer une entité

Une entité est un identifiant auquel on attache des composants. Exemple du sol dans sandbox_scene.h :

sandbox_scene.hC++
Entity ground = registry.createEntity();
registry.addComponent<Transform2D>(ground).setPosition({ 960.f, 550.f });
registry.addComponent<Geometry>(ground,
    Geometry::BoxData{ { 960.f, 8.f }, { sf::Color(100, 100, 100), sf::Color::Transparent, 0.f, "" } }, 0);
registry.addComponent<RigidBody2D>(ground).isStatic = true;
registry.addComponent<Collider2D>(ground, Collider2D::makeBox({ 960.f, 8.f }));
registry.addComponent<NameComponent>(ground, "Ground");

Ajoutez toujours un NameComponent : c'est lui qui donne un nom lisible à l'entité dans la Hierarchy de l'éditeur.

Détruire une entité

Appelez registry.destroyEntity(e). La destruction est différée : elle est exécutée par flushPendingDestroys() à la fin de Game::tick, donc sans risque pendant un view. Après le flush, registry.isValid(e) renvoie faux pour l'ancien identifiant.

Ajouter un composant
  1. Créez une structure de données dans include/components/ du module concerné (par exemple engine/core/include/components/health.h).
  2. Ajoutez-la avec registry.addComponent<Health>(e). Aucun enregistrement n'est nécessaire : le pool est créé à la première utilisation.
  3. (Optionnel, pour l'éditeur) ajoutez une entrée à componentDescriptors() dans editor/src/component_descriptors.cpp pour l'afficher dans l'Inspector.
health.hC++
#pragma once
struct Health {
    float current = 100.f;
    float max     = 100.f;
};
Ajouter un système

Héritez de ISystem, choisissez une priorité distincte (voir l'ordre d'exécution) et enregistrez-le dans la scène :

health_system.hC++
class HealthSystem : public ISystem {
public:
    HealthSystem() { priority = 4; }   // après les scripts (2) et les particules (3), avant le rendu

    void onUpdate(Registry& registry, float dt) override {
        registry.view<Health>([&](Entity e, Health& h) {
            if (h.current <= 0.f)
                registry.destroyEntity(e);   // différé : sans danger dans un view
        });
    }
};

// dans la scène :
game.systems().addSystem<HealthSystem>();
Réagir aux collisions

addSystem renvoie une référence au système : on peut y brancher le callback onCollision tout de suite.

scèneC++
auto& collisions = game.systems().addSystem<CollisionSystem>();
collisions.onCollision = [&](const CollisionInfo& info) {
    if (info.isTrigger) {
        // zone de détection : entityA et entityB se chevauchent, sans réponse physique
    }
};

CollisionInfo fournit entityA, entityB, normal (de A vers B), depth, point et isTrigger.

Ajouter un module au moteur
  1. Créez engine/<nom>/ avec un dossier include/ (en-têtes publics) et, si besoin, src/ (fichiers .cpp).
  2. Dans engine/<nom>/CMakeLists.txt :
engine/scene/CMakeLists.txtCMake
av_module(Scene DEPS AngeVault::Core AngeVault::Tilemap)
  1. Ajoutez add_subdirectory(scene) dans engine/CMakeLists.txt.
  2. Ajoutez AngeVault::Scene à la liste de target_link_libraries(av_engine INTERFACE …) pour que l'éditeur et les projets le voient.

Sans fichier .cpp dans src/, le module est de type INTERFACE (100 % en-têtes) ; avec des sources, c'est une bibliothèque statique. C'est la fonction av_module qui décide.

Ajouter une action d'entrée

Une action est un nom (« Jump », « Horizontal ») relié à des touches par le fichier assets/input.cfg du projet. Deux façons de l'ajouter :

  1. Dans l'éditeur : Édition → Input Manager…, ajoutez l'action, choisissez son type (Button ou Axis) et ses liens. Le fichier est enregistré à chaque modification.
  2. À la main dans input.cfg :
assets/input.cfgShell
[Jump] button
key Space
joybutton 0 0

[Horizontal] axis
key Left -1
key Right

Puis, dans un comportement :

comportementC++
if (Input::getButtonDown("Jump")) rb.applyImpulse({ 0.f, -jumpForce });
const float moveX = Input::getAxis("Horizontal");   // -1..1

Pour des valeurs par défaut sans fichier, ajoutez l'action dans defaultRpgInput (rpg_scene.h) avec input.addAction("Jump").

Faire suivre une entité par la caméra

Une caméra est une entité avec un Transform2D et un Camera2d. Donnez-lui une cible avec setTarget et ajoutez le CameraSystem (qui règle la vue de la fenêtre) à la scène :

rpg_scene.hC++
Entity cameraEntity = registry.createEntity();
registry.addComponent<Transform2D>(cameraEntity);
auto& camera = registry.addComponent<Camera2d>(cameraEntity);
camera.setWorldBorder({ 0.f, 0.f }, { 3000.f, 3000.f });   // optionnel : limites du monde
camera.setTarget(player);

// dans loadRpgScene :
game.systems().addSystem<CameraSystem>(game.window());     // priorité -10 : avant tout le rendu

Dans l'éditeur, la même chose se fait en glissant la caméra sur l'entité à suivre dans la Hierarchy ; elle se place alors sur sa cible et ne se déplace plus à la main. Sans cible, la caméra est libre : flèches pour la déplacer, + / − pour zoomer.

Ajouter une texture à une entité

Déposez l'image dans projects/rpg/assets/ (ou projects/sandbox/assets/ pour le Sandbox) : elle est copiée à côté de l'exécutable après chaque build (av_copy_assets). Puis utilisez son identifiant dans un Geometry::SpriteData :

scèneC++
registry.addComponent<Geometry>(player,
    Geometry::SpriteData{ "player", sf::IntRect({0, 0}, {32, 64}), sf::Color::White }, 1);

Si l'image n'est pas trouvée, un damier magenta s'affiche à la place et la console indique couldn't find ….

Glossaire

TermeDéfinition
ECSEntity-Component-System : les objets de jeu sont des identifiants (entités) portant des données (composants), traités par des systèmes.
EntitéUn identifiant { index, generation }. N'a ni données ni méthodes.
ComposantUne structure de données attachée à une entité (RigidBody2D…).
SystèmeUne classe ISystem qui parcourt les composants à chaque frame, par ordre de priorité.
RegistryL'objet qui possède les entités et les pools de composants.
Sparse setStructure de stockage avec un tableau dense (données contiguës) et un tableau épars (index par entité).
Dual-gridTechnique de tilemap où le visuel est posé sur les sommets entre quatre tuiles, pour des transitions de terrain avec peu de textures.
BehaviorUne classe C++ héritant d'IBehavior, attachée via le composant Script.
Action (entrée)Un nom (« Horizontal », « Jump ») relié à des touches, des boutons de souris, la molette ou une manette par input.cfg ; lu avec Input::getAxis ou Input::getButtonDown.
AxeUne action qui renvoie une valeur réelle entre −1 et 1 (déplacement, par exemple), par opposition à un bouton qui est enfoncé ou non.
CatégorieUn dossier de la Hierarchy pour ranger les entités ; n'existe que dans l'éditeur.
DockUn panneau déplaçable de l'éditeur (QDockWidget).
QSSQt Style Sheets : le langage de thème de l'éditeur, proche du CSS.

FAQ

Pourquoi mes textures s'affichent-elles en damier magenta ?

Le chargeur n'a pas trouvé le fichier. Vérifiez que l'image est dans le dossier assets/ du projet (projects/rpg/assets/ ou projects/sandbox/assets/, copié dans bin/assets au build) et que l'identifiant utilisé correspond à un chemin valide depuis le dossier de l'exécutable.

L'éditeur n'est pas construit, que faire ?

CMake n'a pas trouvé Qt 6. Indiquez son dossier avec CMAKE_PREFIX_PATH ou la variable d'environnement QT_ROOT. Voir Démarrage & build.

Puis-je compiler sans Qt ?

Oui : le preset x64-debug-no-editor (ou -DAV_BUILD_EDITOR=OFF) construit le moteur, les projets (RPG et Sandbox) et les tests sans Qt.

Où sont les sources de l'ancien prototype RTS ?

Dans legacy/rts/ : composants, systèmes et utilitaires conservés comme référence, non compilés par le CMake actuel.
