Créer une entité

Une entité est un identifiant auquel on attache des composants. Exemple du sol dans sandbox_scene.h :

sandbox_scene.hC++
Entity ground = registry.createEntity();
registry.addComponent<Transform2D>(ground).setPosition({ 960.f, 550.f });
registry.addComponent<Geometry>(ground,
    Geometry::BoxData{ { 960.f, 8.f }, { sf::Color(100, 100, 100), sf::Color::Transparent, 0.f, "" } }, 0);
registry.addComponent<RigidBody2D>(ground).isStatic = true;
registry.addComponent<Collider2D>(ground, Collider2D::makeBox({ 960.f, 8.f }));
registry.addComponent<NameComponent>(ground, "Ground");

Ajoutez toujours un NameComponent : c'est lui qui donne un nom lisible à l'entité dans la Hierarchy de l'éditeur.

Détruire une entité

Appelez registry.destroyEntity(e). La destruction est différée : elle est exécutée par flushPendingDestroys() à la fin de Game::tick, donc sans risque pendant un view. Après le flush, registry.isValid(e) renvoie faux pour l'ancien identifiant.

Ajouter un composant (propre à un jeu)

Un composant de jeu va dans le dossier components/ du projet. Une ligne REGISTER_COMPONENT le rend visible dans l'Inspector et le fait enregistrer dans les scènes et les prefabs :

projects/rpg/components/health.hC++
#pragma once
#include "ecs/game_components.h"

struct Health {
    float current = 100.f;
    float max     = 100.f;
};
REGISTER_COMPONENT(Health, FIELD(current), FIELD(max))

Recompilez, puis Inspector → Ajouter un composant → Health. Détails dans Code de jeu.

Ajouter un composant au moteur
  1. Créez une structure de données dans include/components/ du module concerné (par exemple engine/core/include/components/health.h).
  2. Ajoutez-la avec registry.addComponent<Health>(e). Aucun enregistrement n'est nécessaire : le pool est créé à la première utilisation.
  3. (Pour l'éditeur) ajoutez une entrée à componentDescriptors() dans editor/src/component_descriptors.cpp pour l'afficher dans l'Inspector.
  4. (Pour la sauvegarde) enregistrez un sérialiseur : SerializerRegistry::get().add<Health>(…) (voir Projet & sauvegarde).
Écrire un comportement et l'attacher à une entité
  1. Panneau Project → clic droit → Créer (C++) → Behavior…, ou un fichier dans behaviors/.
  2. Héritez de IBehavior, déclarez vos réglages avec PROPERTY, ajoutez REGISTER_BEHAVIOR(MaClasse).
  3. Recompilez, puis glissez le fichier .h sur une entité (ou Ajouter un composant → Comportement).
projects/rpg/behaviors/saut.hC++
class Saut : public IBehavior {
public:
    PROPERTY(float, force, 500.f)
    void onUpdate(Entity self, Registry& registry, float dt) override {
        if (Input::getButtonDown("Jump"))
            registry.getComponent<RigidBody2D>(self).applyImpulse({ 0.f, -force });
    }
};
REGISTER_BEHAVIOR(Saut)
Ajouter un système

Héritez de ISystem, choisissez une priorité (voir l'ordre d'exécution) et ajoutez REGISTER_SYSTEM : le système est ajouté tout seul à chaque Game. Placez-le dans systems/ du projet :

projects/rpg/systems/health_system.hC++
#include "game_systems.h"
#include "../components/health.h"

class HealthSystem : public ISystem {
public:
    HealthSystem() { priority = 4; }   // après les scripts (2) et les particules (3), avant le rendu

    void onUpdate(Registry& registry, float dt) override {
        registry.view<Health>([&](Entity e, Health& h) {
            if (h.current <= 0.f)
                registry.destroyEntity(e);   // différé : sans danger dans un view
        });
    }
};

REGISTER_SYSTEM(HealthSystem)

Pour un système du moteur (ou un test), on l'ajoute à la main : game.systems().addSystem<HealthSystem>(). On peut désactiver n'importe quel système sans le retirer : Exécuter → Systèmes… dans l'éditeur, ou game.systems().setEnabled("HealthSystem", false).

Enregistrer et charger une scène
scèneC++
SceneMeta meta;
saveScene(registry, meta, "scenes/niveau1.scene", &error);            // éditeur : Ctrl+S

clearRegistry(registry);                                              // vider avant de charger
SceneLoadResult r = loadScene(registry, meta, "scenes/niveau1.scene");
for (const std::string& w : r.warnings) std::cerr << w << "\n";

Les liens entre entités survivent grâce aux PersistentId. Voir Projet & sauvegarde.

Faire apparaître un prefab depuis le code

Créez le prefab dans l'éditeur (clic droit sur une entité → Créer un prefab), puis, dans un comportement :

comportementC++
SceneLoadResult r = instantiatePrefabFile(registry, "prefab/Ennemi.prefab", sf::Vector2f{ 400.f, 200.f });
if (r.ok) Entity ennemi = r.entities.front();   // la racine du prefab

Chaque instance reçoit de nouveaux identifiants ; les liens internes au prefab sont conservés. Le chemin est relatif au dossier de lancement de l'exécutable (passez-le avec project.resolve(…) pour qu'il soit relatif au projet).

Créer une carte et lui donner des images
  1. Hierarchy → + → Tilemap orthogonale ou isométrique.
  2. Tile Palette → + → Nouveau tileset depuis une feuille (PNG)… : réglez la taille d'une tile, le type (simple ou autotile) et l'ancre.
  3. Choisissez une tile (ou cochez Autotile) et peignez avec B.
  4. Ctrl+S : le .map et le .tileset sont enregistrés, la scène référence la carte.

Détails et formats : Tilemaps & tilesets.

Réagir aux collisions

addSystem renvoie une référence au système : on peut y brancher le callback onCollision tout de suite.

scèneC++
auto& collisions = game.systems().addSystem<CollisionSystem>();
collisions.onCollision = [&](const CollisionInfo& info) {
    if (info.isTrigger) {
        // zone de détection : entityA et entityB se chevauchent, sans réponse physique
    }
};

CollisionInfo fournit entityA, entityB, normal (de A vers B), depth, point et isTrigger.

Ajouter un module au moteur
  1. Créez engine/<nom>/ avec un dossier include/ (en-têtes publics) et, si besoin, src/ (fichiers .cpp).
  2. Dans engine/<nom>/CMakeLists.txt :
engine/scene/CMakeLists.txtCMake
av_module(Scene DEPS AngeVault::Core AngeVault::Physics2D AngeVault::Render2D nlohmann_json::nlohmann_json)
  1. Ajoutez add_subdirectory(scene) dans engine/CMakeLists.txt (c'est le cas du module scene, donné ici en exemple).
  2. Ajoutez AngeVault::Scene à la liste de target_link_libraries(av_engine INTERFACE …) pour que l'éditeur et les projets le voient.

Sans fichier .cpp dans src/, le module est de type INTERFACE (100 % en-têtes) ; avec des sources, c'est une bibliothèque statique. C'est la fonction av_module qui décide.

Ajouter une action d'entrée

Une action est un nom (« Jump », « Horizontal ») relié à des touches par le fichier assets/input.cfg du projet. Deux façons de l'ajouter :

  1. Dans l'éditeur : Édition → Input Manager…, ajoutez l'action, choisissez son type (Button ou Axis) et ses liens. Le fichier est enregistré à chaque modification.
  2. À la main dans input.cfg :
assets/input.cfgShell
[Jump] button
key Space
joybutton 0 0

[Horizontal] axis
key Left -1
key Right

Puis, dans un comportement :

comportementC++
if (Input::getButtonDown("Jump")) rb.applyImpulse({ 0.f, -jumpForce });
const float moveX = Input::getAxis("Horizontal");   // -1..1

Le chemin du fichier est celui de paths.input dans le .angproj. Pour des valeurs par défaut sans fichier, ajoutez l'action dans defaultRpgInput (rpg_scene.h) avec input.addAction("Jump").

Faire suivre une entité par la caméra

Une caméra est une entité avec un Transform2D et un Camera2d. Le suivi est un composant à part, CameraFollow ; les systèmes caméra s'enregistrent d'un coup avec registerCameraSystems :

rpg_scene.hC++
Entity cameraEntity = registry.createEntity();
registry.addComponent<Transform2D>(cameraEntity);
registry.addComponent<Camera2d>(cameraEntity);
Camera::follow(registry, cameraEntity, player);            // ajoute CameraFollow et fixe la cible
registry.addComponent<CameraBounds>(cameraEntity).set({ 0.f, 0.f }, { 3000.f, 3000.f });   // optionnel : limites du monde

// dans registerRpgSystems (déjà fait dans le RPG) :
registerCameraSystems(game.systems(), game.target());      // Control, Follow, Bounds, Shake puis CameraSystem (priorité 7)

Dans l'éditeur, la même chose se fait en glissant la caméra sur l'entité à suivre dans la Hierarchy ; elle se place alors sur sa cible et ne se déplace plus à la main. Sans cible, la caméra est libre : si elle a un CameraControl, les actions CameraX / CameraY la déplacent, et la molette (ZoomWheel) zoome dans les deux cas. CameraFollow::lookAhead fait anticiper le mouvement de la cible, smoothTime et deadZone règlent la souplesse. Pour un choc ou une explosion : Camera::shake(registry, 0.5f). Détail des champs : Référence des composants.

Ajouter une texture à une entité

Déposez l'image dans projects/rpg/assets/ (ou projects/sandbox/assets/ pour le Sandbox) : elle est copiée à côté de l'exécutable après chaque build (av_copy_assets). Puis utilisez son identifiant dans un Geometry::SpriteData :

scèneC++
registry.addComponent<Geometry>(player,
    Geometry::SpriteData{ "player", sf::IntRect({0, 0}, {32, 64}), sf::Color::White }, 1);

Si l'image n'est pas trouvée, un damier magenta s'affiche à la place et la console indique couldn't find ….

Glossaire

TermeDéfinition
ECSEntity-Component-System : les objets de jeu sont des identifiants (entités) portant des données (composants), traités par des systèmes.
EntitéUn identifiant { index, generation }. N'a ni données ni méthodes.
ComposantUne structure de données attachée à une entité (RigidBody2D…).
SystèmeUne classe ISystem qui parcourt les composants à chaque frame, par ordre de priorité.
RegistryL'objet qui possède les entités et les pools de composants.
Sparse setStructure de stockage avec un tableau dense (données contiguës) et un tableau épars (index par entité).
Dual-gridTechnique de tilemap où le visuel est posé sur les sommets entre quatre tuiles, pour des transitions de terrain avec peu de textures (autotile corners16).
Projet (.angproj)Le fichier qui décrit un jeu : scène de départ, scènes, dossiers, fenêtre, systèmes actifs.
Scène (.scene)Un fichier JSON qui contient des entités et leurs composants.
Prefab (.prefab)Un groupe d'entités enregistré pour être recréé à volonté.
PersistentIdIdentifiant stable d'une entité, écrit dans les fichiers : il relie les entités entre elles, là où l'index mémoire change à chaque chargement.
Tileset (.tileset)Une feuille d'images découpée en grille, avec ses réglages (ancre, autotile, tri en Y).
Tilemap (.map)Une carte : une grille de cases « tileset + tile ». Posée sur une entité par le composant Tilemap.
AutotileUn tileset dont les pièces de transition (bords, coins) sont choisies automatiquement d'après les cases voisines.
Tri en YDessiner les objets du plus haut au plus bas de l'écran pour que les personnages passent devant ou derrière arbres et murs.
REGISTER_*Les macros REGISTER_BEHAVIOR, REGISTER_COMPONENT et REGISTER_SYSTEM qui déclarent le code d'un jeu à l'éditeur, aux scènes et à Game.
BehaviorUne classe C++ héritant d'IBehavior, attachée via le composant Script.
Action (entrée)Un nom (« Horizontal », « Jump ») relié à des touches, des boutons de souris, la molette ou une manette par input.cfg ; lu avec Input::getAxis ou Input::getButtonDown.
AxeUne action qui renvoie une valeur réelle entre −1 et 1 (déplacement, par exemple), par opposition à un bouton qui est enfoncé ou non.
CatégorieUn dossier de la Hierarchy pour ranger les entités ; n'existe que dans l'éditeur.
DockUn panneau déplaçable de l'éditeur (QDockWidget).
QSSQt Style Sheets : le langage de thème de l'éditeur, proche du CSS.

FAQ

Pourquoi mes textures s'affichent-elles en damier magenta ?

Le chargeur n'a pas trouvé le fichier. Vérifiez que l'image est dans le dossier assets/ du projet (projects/rpg/assets/ ou projects/sandbox/assets/, copié dans bin/assets au build) et que l'identifiant utilisé correspond à un chemin valide depuis le dossier de l'exécutable.

L'éditeur n'est pas construit, que faire ?

CMake n'a pas trouvé Qt 6. Indiquez son dossier avec CMAKE_PREFIX_PATH ou la variable d'environnement QT_ROOT. Voir Démarrage & build.

Puis-je compiler sans Qt ?

Oui : le preset x64-debug-no-editor (ou -DAV_BUILD_EDITOR=OFF) construit le moteur, les projets (RPG et Sandbox) et les tests sans Qt.
