FAQ & dépannage

Les questions qui reviennent, et ce qu'il faut vérifier quand quelque chose ne marche pas : compilation, éditeur, scènes, cartes, entrées.

Compilation

ProblèmeÀ vérifier
CMake dit que Qt est introuvableDéfinissez la variable d'environnement QT_ROOT ou passez -DCMAKE_PREFIX_PATH=… (voir Démarrage & build) ou utilisez le preset x64-debug-no-editor pour ne construire que le moteur, les projets et les tests
La première configuration est longueNormal : SFML et glm sont téléchargés par FetchContent. Les suivantes sont rapides
Un nouveau fichier de behaviors/, components/ ou systems/ n'est pas pris en compteRelancez la compilation : le glob de CMake est en CONFIGURE_DEPENDS et regénère l'en-tête rpg_game_code.h tout seul
Erreur « SFML::… introuvable » dans un nouveau moduleAjoutez la cible dans DEPS de av_module(…) (recette « Ajouter un module » dans la documentation)
Un test ne compile pas après avoir changé l'APILes tests sont construits avec le projet (AV_BUILD_TESTS). Voir la feuille de route : test_tilemap a été écrit pour l'ancienne API des cartes

Éditeur

ProblèmeÀ vérifier
Mon comportement, composant ou système n'apparaît pasRecompilez l'éditeur ; la ligne REGISTER_… est-elle présente ? Le fichier est-il dans le bon dossier du projet ? Voir Code de jeu
Ctrl+F5 dit que rpg.exe est introuvableCompilez la cible rpg (elle est aussi une dépendance de l'éditeur : une compilation complète la construit)
Le jeu lancé dans l'éditeur ne bouge pasLa vue du jeu doit avoir le focus : cliquez dedans. Les touches viennent de l'Input Manager : vérifiez les actions Horizontal et Vertical et que le comportement du joueur est bien attaché
Ma carte n'affiche rienLe tileset est-il ajouté à la carte (Tile Palette → +) ? Le composant Tilemap est-il visible ? Le message « introuvable » à côté d'un tileset signale un fichier déplacé
Les transitions d'herbe sont faussesVérifiez les rôles des tiles dans la fenêtre Tileset (Disposition standard) et l'ordre des tilesets : un autotile doit être après ceux sur lesquels il déborde
Je ne peux pas déplacer la caméraElle suit une entité (composant CameraFollow, champ target). Clic droit → Suivre → (Personne : caméra libre). Pour la piloter à la main en jeu, ajoutez un CameraControl à une caméra sans cible
Le jeu dessine des contours verts ou des flèchesCe sont les systèmes de debug : décochez-les dans Exécuter → Systèmes… (RenderCollisionSystem, ForceDebugSystem)
L'éditeur est tout rose / tout sombreMenu Édition → Thème
Le jeu est flou, saccadé ou trop sombre / trop contrastéRegardez Édition → Paramètres du jeu… : antialiasing, vsync, limite de FPS et shader de post-process. Un shader qui ne compile pas est désactivé (message dans la Console)
Ma caméra ne bouge pas, ne tremble pas ou ne suit rien en jeuLe projet doit appeler registerCameraSystems(game.systems(), game.target()) (fait dans registerRpgSystems), et la caméra doit avoir le composant voulu (CameraFollow, CameraControl, CameraShake). Avec plusieurs caméras, seule la plus prioritaire et active est affichée
Un système que j'ai écrit dans engine/ ne s'exécute pasAucun système du moteur n'est ajouté tout seul : ajoutez-le dans Game::init() ou dans une fonction registerXxxSystems appelée par le projet (voir Créer un système (côté engine))
Mon composant du moteur disparaît à l'enregistrementIl manque son sérialiseur : reg.addReflected<T>("Nom") dans registerBuiltins (voir Créer un composant (côté engine))

Scènes et fichiers

ProblèmeCause et remède
Avertissement « comportement inconnu »Le nom écrit dans le .scene ne correspond à aucune classe enregistrée (classe renommée ou supprimée, ou code non recompilé). L'entité est chargée sans ce comportement
Avertissement « composant inconnu »Même cause pour un composant. Le reste de la scène se charge normalement
Une caméra ne suit plus sa cible après le chargementLa cible n'est plus dans la scène : le lien devient vide (avec un avertissement)
« ancien format (une image par tile) »Carte de version 1 : convertissez-la avec tools/convert_tilemaps.py (voir Tilemaps & tilesets)
Textures magenta et noiresTexture introuvable (damier de secours) : vérifiez l'identifiant ou le chemin de l'image et le dossier assets/ copié à côté de l'exécutable
Le projet ne s'ouvre pas sur un autre posteLes chemins sont relatifs au .angproj : copiez tout le dossier du projet, pas seulement le fichier
Où sont mes modifications après F5 ?Le jeu joue une copie : rien de ce qui se passe en jeu n'est enregistré dans la scène. Modifiez dans l'éditeur, pas pendant le jeu

Entrées

ProblèmeÀ vérifier
rpg.exe ignore mes touchesLe fichier input.cfg est lu à l'emplacement donné par paths.input du .angproj, relatif au projet. Lancé sans projet, le jeu retombe sur les actions par défaut du code
Une action ne renvoie jamais rienLe nom doit correspondre exactement (majuscules comprises) à celui du fichier input.cfg. Hors d'un Game (dans un test), Input:: renvoie toujours 0 ou faux
La manette dériveAugmentez la zone morte de l'axe (0,2 par défaut) dans l'Input Manager

Questions fréquentes

Peut-on utiliser AngeVault sans l'éditeur ?

Oui. Le moteur est indépendant de l'éditeur : Game en mode autonome, des entités créées en C++ comme dans le Sandbox, ou un projet chargé depuis ses fichiers comme dans rpg.exe. Le preset x64-debug-no-editor construit tout sauf l'éditeur.

Faut-il écrire du C++ pour faire un jeu ?

Pour la logique, oui (comportements et systèmes sont du C++). Pour construire les niveaux — cartes, entités, prefabs, réglages — l'éditeur suffit.

Comment ajouter un système ou un composant au moteur ?

Voir Créer un système (côté engine) et Créer un composant (côté engine) : module, priorité, branchement dans Game::init(), sérialiseur et bloc ComponentDesc pour l'Inspector.

Comment ajouter un module au moteur ?

Voir la recette « Ajouter un module » du centre de documentation : un dossier, un CMakeLists.txt d'une ligne avec av_module, et l'ajouter à engine/CMakeLists.txt.

Où signaler un bug ?

Menu Aide → Signaler un bug de l'éditeur, ou une nouvelle issue sur GitHub.
