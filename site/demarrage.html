Démarrage & build

De zéro à l'éditeur qui tourne : prérequis, presets CMake, options de build, lancer le RPG, le Sandbox et les tests.

Prérequis

OutilVersionPour quoi faire
CMake≥ 3.28Génération du build (cmake_minimum_required(VERSION 3.28))
Compilateur C++20MSVC 2022 (Windows)Les presets Windows utilisent cl.exe
Ninja—Générateur utilisé par les presets
Git + accès réseau—SFML 3.1.0, glm 1.0.1 et nlohmann_json 3.11.3 (lecture / écriture JSON) sont téléchargés au premier configure (FetchContent)
Qt 6 (Widgets)kit MSVC 2022 64-bitÉditeur uniquement — le moteur, le RPG et le Sandbox n'en ont pas besoin

Sous Windows, si Qt6_DIR et CMAKE_PREFIX_PATH ne sont pas définis, CMake cherche tout seul le kit le plus récent dans C:/Qt/6.*/msvc*_64 et l'affiche (Qt detecte automatiquement).

Configurer et compiler

Les presets ouvrent directement dans CLion ou Visual Studio ; en ligne de commande :

terminalShell
# 1. (si Qt n'est pas détecté automatiquement) indiquer le kit Qt
set QT_ROOT=C:/Qt/6.8.1/msvc2022_64

# 2. configurer (télécharge SFML et glm la première fois)
cmake --preset x64-debug

# 3. compiler
cmake --build out/build/x64-debug

Les exécutables sont produits dans out/build/<preset>/bin/ : AngeVaultEditor.exe, rpg.exe, Sandbox.exe et les tests (test_component_pool, test_math, test_scene, test_tilemap).

Les presets

PresetDescription
x64-debugWindows, MSVC, Debug, avec l'éditeur
x64-releaseComme le précédent, en Release
x64-debug-no-editorDebug sans Qt (AV_BUILD_EDITOR=OFF)
devLinux / macOS, Debug (le dossier de build est out/build/dev)

Tous les presets partagent binaryDir = ${sourceDir}/out/build/${presetName} et lisent QT_ROOT pour CMAKE_PREFIX_PATH. Pour garder un chemin Qt personnel hors du dépôt, copiez CMakeUserPresets.example.json en CMakeUserPresets.json (déjà ignoré par Git) et corrigez-le.

Les options

terminalShell
cmake --preset x64-debug -DAV_BUILD_EDITOR=OFF     # sans éditeur
cmake --preset x64-debug -DAV_BUILD_SANDBOX=OFF    # sans Sandbox
cmake --preset x64-debug -DAV_BUILD_RPG=OFF        # sans le projet RPG
cmake --preset x64-debug -DAV_BUILD_TESTS=OFF      # sans tests

Lancer le RPG

rpg.exe lit son projet : il charge rpg.angproj (fenêtre, systèmes actifs, fichier des touches), puis sa scène de départ (scenes/main.scene) et les cartes qu'elle utilise. CMake copie rpg.angproj, le dossier scenes/ et les assets à côté de l'exécutable, dans bin/.

terminalShell
rpg.exe                                         # rpg.angproj à côté de l'exécutable, scène de départ
rpg.exe chemin/vers/rpg.angproj                 # un autre projet
rpg.exe chemin/vers/rpg.angproj scenes/iso_demo.scene   # une scène précise

La scène main.scene montre un joueur déplacé par l'Input Manager et une caméra qui le suit ; iso_demo.scene montre une carte isométrique. Si le projet ou la scène est illisible, rpg.exe écrit l'erreur et retombe sur la scène écrite en C++ (rpg_scene.h). Les avertissements de chargement (comportement ou composant inconnu, carte introuvable) sont écrits sur la sortie d'erreur.

Touche (par défaut)Action de l'Input Manager
← → / Q D / A / stick gaucheHorizontal : déplacement gauche / droite
↑ ↓ / Z S / W / stick gaucheVertical : déplacement haut / bas
MoletteZoomWheel : zoom de la caméra (sauf si elle est verrouillée)
ÉchapQuitter

Les touches se changent sans recompiler, dans assets/input.cfg ou depuis l'éditeur (Édition → Input Manager…). Les actions Zoom, ZoomWheel, CameraX et CameraY sont celles du composant CameraControl (pan et zoom de la caméra libre). Les réglages d'affichage (plein écran, vsync, antialiasing, shader) sont dans assets/settings.cfg, ou Édition → Paramètres du jeu…. Les systèmes de debug (ForceDebugSystem) sont désactivés dans rpg.angproj.

Lancer le Sandbox

Sandbox.exe ouvre sa propre fenêtre 1920×1080, charge la scène de sandbox_scene.h et lance la boucle. Les textures sont copiées dans bin/assets après chaque build.

Espace / Z / W / ↑Sauter (double saut possible)
ETirer une balle (au plus une toutes les 2 secondes)

Lancer l'éditeur

Lancez AngeVaultEditor.exe. Il rouvre le dernier projet (sinon le RPG, projects/rpg/rpg.angproj) et sa scène de départ ; sélectionnez une entité pour éditer ses composants dans l'Inspector. Le guide de l'éditeur détaille chaque étape ; en bref :

  1. Projet : Fichier → Nouveau projet… ou Ouvrir… (Ctrl+O) ; Ctrl+S enregistre la scène en .scene.
  2. Carte : bouton + de la Hierarchy → Tilemap orthogonale ou isométrique ; dans la Tile Palette, + pour ajouter un tileset ; pinceau B, gomme E, remplir G, pipette I.
  3. Jouer : F5 lance la scène dans l'éditeur, F6 met en pause, Maj+F5 arrête. Ctrl+F5 lance rpg.exe dans sa propre fenêtre (après avoir enregistré la scène).
  4. Régler les touches : Édition → Input Manager… ; un jeu lancé avec F5 prend les changements tout de suite.
  5. Systèmes : Exécuter → Systèmes… pour activer ou désactiver les systèmes (enregistré dans le .angproj).
  6. Code : clic droit dans le panneau Project → Créer (C++) ; recompilez, puis glissez le fichier sur une entité (Code de jeu).
  7. Annuler : Ctrl+Z / Ctrl+Y.
  8. Thème : Édition → Thème (8 thèmes, ou un fichier .qss).

Lancer les tests

terminalShell
ctest --test-dir out/build/x64-debug --output-on-failure
  • test_component_pool vérifie le sparse set : ajout / lecture, retrait avec swap & pop, callbacks onDestroy et retrait du dernier élément.
  • test_scene vérifie la sauvegarde : un joueur complet et sa caméra rechargés dans un registre aux index décalés (le lien suit grâce au PersistentId), plusieurs comportements sur une entité, l'ancien format à un seul "behavior", les prefabs instanciés deux fois (chaque caméra suit son joueur), une deuxième sauvegarde identique, un fichier abîmé (composant inconnu, cible disparue, JSON invalide), le projet .angproj et un composant de jeu REGISTER_COMPONENT.
  • test_tilemap vérifie les cartes : conversions case ↔ monde en orthogonal et en isométrique, cases, redimensionnement, fichier .map et chemins relatifs. Attention : il utilise encore l'ancienne interface (removeTile, tile(), cases "40*1") et ne correspond plus à tilemap.h actuel : il est à réécrire (voir la feuille de route).
  • test_math vérifie les outils de maths du Core : lerp, inverseLerp, remap, moveTowards (sans dépasser la cible), damp et dampHalfLife, smoothDamp, les angles (deltaAngle, lerpAngle…), pingPong, repeat, normalize, et que chacune des 22 courbes d'Ease vaut 0 en 0 et 1 en 1.

Dépannage

« Qt 6 introuvable : l'éditeur n'est PAS construit »

Le moteur et le Sandbox sont tout de même construits. Installez Qt 6 (kit MSVC 2022 64-bit) et passez son dossier : cmake -DCMAKE_PREFIX_PATH=C:/Qt/6.8.1/msvc2022_64 … ou définissez QT_ROOT.

Le premier configure est long ou échoue

SFML et glm sont récupérés par Git depuis GitHub (GIT_SHALLOW), nlohmann_json par une archive de version. Vérifiez l'accès réseau ; les téléchargements ne se refont pas aux configurations suivantes.

« rpg.exe introuvable » depuis l'éditeur

Ctrl+F5 cherche rpg.exe à côté de l'éditeur. La cible rpg est une dépendance de l'éditeur : recompilez le projet entier (et vérifiez que AV_BUILD_RPG est à ON).

Les touches de rpg.exe ne suivent pas mes réglages

rpg.exe lit le fichier indiqué par paths.input de son .angproj (par défaut assets/input.cfg), relatif au dossier du projet. Lancé depuis l'éditeur (Ctrl+F5), il reçoit le .angproj du projet source : ses réglages sont donc ceux de l'éditeur. Lancé à la main depuis bin/, il lit la copie faite par av_copy_assets : relancez un build pour la mettre à jour. Si le fichier est absent, les actions par défaut du code sont utilisées.

Une scène ne charge pas, ou affiche des avertissements

Consultez la Console de l'éditeur (ou la sortie d'erreur de rpg.exe) : un comportement ou composant inconnu, une carte ou un tileset introuvable y sont signalés. Voir la FAQ & dépannage.

Les textures sont des damiers magenta

Les assets sont copiés dans bin/assets par av_copy_assets après le build. Relancez un build puis exécutez le programme depuis son dossier bin/.
