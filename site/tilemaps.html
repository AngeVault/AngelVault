Tilemaps & tilesets

Comment AngeVault décrit et dessine les cartes : fichiers .map et .tileset, autotile, isométrique, tri en Y, et l'outil de conversion.

Le principe : la carte ne contient que des numéros

Une carte ne sait pas à quoi ressemblent ses cases. Elle contient seulement, pour chaque case, « tel tileset, telle tile ». L'apparence vient des tilesets : des feuilles d'images (PNG) découpées en grille. Changer d'herbe, c'est changer de tileset, sans toucher à la carte.

Le composant Tilemap

Une tilemap est un composant, pas un objet à part : on le pose sur une entité. Pas de composant, pas de carte. Le Transform2D de l'entité donne la position de la carte dans le monde, et une scène peut en contenir zéro, une ou plusieurs (une par étage, par exemple).

tilemap/tilemap.hC++
struct Tilemap {
    std::string file;                      // .map, relatif au projet (ex. "maps/village.map")
    bool visible = true;                   // décocher pour la masquer sans la supprimer
    std::shared_ptr<TileMapData> data;     // chargée depuis `file` par loadTilemaps()
};

Dans la scène on n'enregistre que file et visible. Les cases restent dans le fichier .map, que l'éditeur écrit quand on enregistre.

Cases : TileCell

Une case est un entier de 32 bits : les 16 bits du haut désignent le tileset (compté + 1, 0 = case vide), les 16 bits du bas la tile dans la feuille, ou la valeur spéciale kAutoTile (0xFFFF) pour « autotile ».

tilemap/tilemap.hC++
TileCell c = makeCell(2, 15);     // tileset n°2, tile 15
cellSlot(c);                      // 2     (-1 si la case est vide)
cellTile(c);                      // 15
cellIsAuto(makeCell(2, kAutoTile));   // vrai : le terrain du tileset n°2, pièce choisie selon les voisines

Les méthodes de TileMapData : get(x, y), set(x, y, cellule) (renvoie faux si hors carte ou inchangé), fill, resize (garde le coin haut-gauche), et la gestion des tilesets (addTileset, removeTileset, moveTileset, tilesetSlot). version est incrémenté à chaque modification : le rendu et l'éditeur s'en servent pour ne refaire que ce qui a changé.

Le fichier .map

Format angeVault.tilemap, version 2. Les cases sont écrites une ligne de texte par rangée, compressées : 0 = vide, 2:15 = tileset 2 (compté depuis 0), tile 15, 2:a = tileset 2 en autotile, 12*2:a = 12 fois la même case.

maps/exemple.mapJSON
{
  "format": "angeVault.tilemap",
  "version": 2,
  "orientation": "isometric",
  "tileSize": [128, 64],
  "size": [6, 4],
  "tilesets": [
    "assets/tilesets/iso_demo/herbe.tileset",
    "assets/tilesets/iso_demo/arbres.tileset"
  ],
  "cells": [
    "6*0:a",
    "0:a 0:a 0:a 0:a 0:a 0:a",
    "0:a 0:a 1:3 0:a 0:a 0:a",
    "6*0:a"
  ]
}

Anciennes cartes. Les cartes de version 1 (« une image par tile », 8 types de terrain codés en dur) ne sont plus lues : le chargement s'arrête avec « ancien format ». Convertissez-les avec l'outil décrit plus bas.

Un tileset introuvable n'empêche pas de charger la carte : il est gardé avec l'indicateur missing, ses cases restent dans le fichier, et un avertissement est ajouté. On ne perd donc rien si un fichier est déplacé par erreur.

Orthogonal ou isométrique

OrthogonalIsométrique
orientation"orthogonal""isometric"

cellCenter(x, y), cellAt(point) et cellCorners(x, y) convertissent entre cases et coordonnées de la carte dans les deux orientations. localSize() et localOrigin() donnent la boîte englobante (en isométrique, la carte s'étend aussi vers les x négatifs : localOrigin() vaut (−hauteur · w/2, 0)). Ce sont des coordonnées locales : ajoutez le Transform2D de l'entité pour le monde.

anchorLe point de la tile (en pixels de la feuille) posé sur le centre de la case. [-1, -1] = automatique : centre de la tile, étirée à la case en orthogonal. Indispensable pour les tiles iso plus hautes que le losange (arbres, murs)

Autotile : trois façons d'utiliser un tileset

Tileset simple (none)

On choisit une tile dans la grille (ou un bloc de tiles, qu'on pose d'un coup comme un tampon) et on la pose telle quelle. Rien d'automatique.

edges16 : des pièces sur les cases voisines

Format des packs isométriques : l'herbe « déborde » sur la terre voisine. Le fichier indique, pour chaque rôle, les numéros de tile de la feuille :

ChampQuand la pièce est utilisée
fullCase entourée de terrain : pièce pleine. Plusieurs numéros = variantes, choisies au hasard mais de façon stable (la même case donne toujours la même variante)
edge[4]Un bord libre (un par direction)
corner[4]Deux bords libres adjacents (le bord i et le bord i + 1)
ringLes quatre bords libres (facultatif : sinon deux « coins »)
underDessinée sous la case pleine, par exemple le bloc de terre sous l'herbe

Un autotile plus bas dans la liste des tilesets de la carte déborde sur les cases des tilesets précédents : l'ordre des tilesets est l'ordre d'empilement. Dans la fenêtre Tileset de l'éditeur, le bouton « Disposition standard » remplit tous ces rôles d'un coup pour une feuille rangée dans l'ordre habituel.

corners16 : le « dual-grid »

Une feuille de 16 colonnes : une colonne par combinaison des quatre coins (0 à 15), et une ligne par variante. Le visuel est posé sur les sommets entre quatre cases, ce qui donne des transitions propres avec très peu d'images. Avec frameTime > 0, les lignes sont les images d'une animation (eau qui bouge). Ce mode est pensé pour l'orthogonal ; en isométrique, seule la pièce pleine (colonne 15) est utilisée.

Tri en Y : arbres, murs et personnages

Un tileset marqué "ySort": true n'est pas dessiné avec le sol. Ses tiles sont triées avec les personnages selon leur point de tri : un personnage dont les pieds sont plus haut que ce point passe derrière la tile, plus bas il passe devant.

  • Point de tri : le centre de la case en isométrique, le bas de la case en orthogonal, plus sortOffset (en unités du monde).
  • Le TilemapRenderSystem (priorité 5) dépose ces tiles dans la YSortQueue ; le RenderSystem (priorité 10) les mélange aux entités de la couche YSortQueue::kEntityLayer (1) : donnez layer = 1 à la Geometry de vos personnages, comme le joueur du RPG.
  • Pour une entité, le point de tri est le bas de sa forme (ses pieds).

Dessiner une carte soi-même

Le TilemapRenderSystem dessine toutes les entités qui portent un Tilemap visible, avec les cases visibles seulement (culling). L'éditeur utilise le même code (TilemapRenderer::draw, et drawGhost pour l'aperçu translucide du pinceau) : ce que l'on voit en éditant est ce que le jeu dessine.

usageC++
#include "scene/tilemaps.h"

// Après loadScene : lire les .map des entités Tilemap
std::vector<std::string> warnings;
loadTilemaps(game.registry(), project.directory(), &warnings);

// Retrouver la case sous un point du monde
registry.view<Tilemap, Transform2D>([&](Entity, Tilemap& tm, Transform2D& t) {
    if (!tm.data) return;
    sf::Vector2i cell = tm.data->cellAt(worldPoint - t.getPosition());
    TileCell c = tm.data->get(cell.x, cell.y);
    if (c != 0) { /* il y a quelque chose ici : tm.data->tilesetOf(c) donne le tileset */ }
});

Convertir et ranger des images : tools/convert_tilemaps.py

Un script Python (pip install pillow) fait deux choses.

  1. Convertir d'anciennes cartes (.map version 1) en tilesets :
    terminalShell
    python tools/convert_tilemaps.py maps projects/rpg
    Chaque ancienne tile devient un tileset (feuille PNG + .tileset) dans assets/tilesets/<carte>/, et l'ancien fichier est gardé à côté en .map.v1.
  2. Assembler un pack isométrique « une PNG par tile » en feuilles :
    terminalShell
    python tools/convert_tilemaps.py pack-iso "<dossier Environment>" projects/rpg assets/tilesets/fantasy_iso
    Une feuille par famille (« Ground A », « Wall F »…), avec 4 colonnes pour les rotations N, E, S, O, une ligne par numéro. Le vide commun est rogné et l'ancre recalculée (option --anchor, 128 208 par défaut).

L'éditeur sait faire cet assemblage lui-même : le bouton d'import de la fenêtre Tileset (packTilesetImages) regroupe des images séparées en une feuille, range les rotations nommées _N, _E, _S, _W sur une ligne et peut rogner le vide commun.

Dans l'éditeur

Le panneau Tile Palette montre les tilesets de la carte active (celle de l'entité sélectionnée, sinon la première de la scène) et ses outils. La marche à suivre complète est dans le guide de l'éditeur. Rappel des outils :

ToucheOutilEffet
VSélectionSélectionner et déplacer les entités
BPinceauPeindre la tile ou le bloc choisi, ou le terrain (autotile)
EGommeVider des cases
GRemplirRemplir une zone
IPipetteReprendre la case sous la souris (aussi Alt + clic)
RTaillePoignées pour agrandir la forme et/ou la collision de l'entité sélectionnée
