Architecture

Éditeur Qt

AngeVaultEditor : une application Qt 6 qui embarque SFML, avec un état partagé unique (EditorContext) autour duquel s'organisent tous les panneaux.

Vue d'ensemble

L'éditeur (editor/, cible AngeVaultEditor) est une application Qt 6 Widgets qui lie AngeVault::Engine. Il construit sa fenêtre principale à partir de CustomWindow (une fenêtre sans bordure Windows), y place des panneaux détachables (QDockWidget) et une vue centrale dessinée par SFML.

Pour utiliser l'éditeur, voir plutôt le guide de l'éditeur : cette page décrit sa construction.

EditorContext : le bus central

EditorContext est un QObject qui possède la scène (un Registry), le projet ouvert, l'entité sélectionnée, l'historique, l'outil actif et le pinceau. Les tilemaps sont des composants de la scène : le contexte retient laquelle est active. Règle de l'éditeur : aucun panneau ne parle directement à un autre. Chacun lit et modifie le contexte, puis réagit à ses signaux.

editor/src/editor_context.hC++
signals:
    void sceneChanged();                          // entités ajoutées / supprimées / renommées
    void selectionChanged(Entity e);              // NULL_ENTITY si plus rien n'est sélectionné
    void entityModified(Entity e, QObject* source);
    void componentsChanged(Entity e);             // composants ou comportements ajoutés / retirés
    void followTargetChanged(Entity camera);      // la caméra suit une autre entité (ou plus rien)
    void toolChanged(EditorTool tool);            // Select, Paint, Erase, Fill, Pick, Resize
    void brushChanged(const TileBrush& brush);    // tileset, tile, bloc ou autotile choisi
    void tilemapChanged();                        // autre carte active, ou ses tiles / réglages ont changé
    void dirtyChanged(bool dirty);                // modifications non enregistrées
    void documentChanged();                       // autre projet / scène ouverte ou enregistrée
    void undoStateChanged();                      // canUndo() / canRedo() ont pu changer

Les outils sont EditorTool::Select, Paint, Erase, Fill, Pick, Resize ; ce qu'on peint est un TileBrush (tileset de la carte, tile ou bloc de tiles, ou « autotile »). Le contexte offre aussi :

  • Projet et scène : openProject, openScene, saveScene, saveSceneAs, newScene, setSystemEnabled. Il s'appuie sur le module scene ; sceneSnapshot() donne la scène en JSON, que le mode Jouer charge comme copie.
  • Tilemaps : activeTilemap, activeMap, createTilemap(orientation, largeur, hauteur), addTilemapFromFile (un .map existant), notifyMapEdited et notifyTilesetSaved (les autres cartes qui utilisent le tileset suivent).
  • Comportements et prefabs : addBehavior, removeBehavior, dropFiles (fichiers déposés : .prefab = une instance, .h = les comportements déclarés dedans ajoutés à la cible), createPrefab, instantiatePrefab.
  • Glisser-déposer entre panneaux : un type MIME application/x-angevault-entities transporte des entités de la Hierarchy vers le panneau Project (créer un prefab).

Annuler / Rétablir

Après chaque modification (entités, composants, Hierarchy, tiles peintes), le contexte mémorise un instantané : la scène en JSON (sceneToString + catégories), les cases de chaque tilemap (partagées, copiées seulement si elles changent) et la sélection, identifiée par son PersistentId. undo() et redo() restaurent un instantané. Les modifications rapprochées sont regroupées par un minuteur (la frappe dans l'Inspector) et un geste à la souris compte pour une étape (beginInteraction / endInteraction). C'est la même sérialisation que pour le fichier : tout ce qui se sauvegarde s'annule.

Catégories et caméras liées

Deux notions n'existent que dans l'éditeur, et EditorContext les porte :

  • Catégories : des dossiers pour ranger les entités dans la Hierarchy, comme les objets vides « dossier » d'Unity (addCategory, renameCategory, removeCategory, categoryOf, setCategory). Rien n'est ajouté aux entités du jeu. Les catégories sont enregistrées dans la section editor du fichier .scene. Quand le projet RPG n'a pas encore de scène, main() en crée une depuis loadRpgEntities, en rangeant les caméras libres dans « Caméras » et les entités qui ont un Script dans « Personnages ».
  • Caméras liées (followTarget, setFollowTarget, snapFollowers) : une caméra dont CameraFollow::target est valide est placée sur sa cible et ne peut plus être déplacée à la main (isPositionLocked), puisque c'est ce que fera le CameraFollowSystem en jeu. Quand on déplace la cible, les caméras qui la suivent se replacent.

Tous les panneaux sont des QDockWidget : on peut les déplacer, les empiler en onglets, les faire flotter ou les fermer. Affichage → Fenêtres donne une case à cocher par panneau (Ctrl+Maj+1…5) et un bouton « Réinitialiser la disposition ». La disposition est mémorisée dans QSettings avec un numéro de version (3 aujourd'hui : une ancienne disposition d'une version précédente est ignorée).

Afficher un composant dans l'Inspector

L'Inspector ne connaît pas les composants : il lit componentDescriptors(). Chaque champ a un getter et un setter ; cela fonctionne donc aussi pour les champs privés (Transform2D::setPosition) et pour les variantes (la forme d'un Collider2D).

editor/src/component_descriptors.hC++
enum class FieldKind { Float, Int, Bool, Vec2, String, Color, Label, Choice };

struct FieldDesc {
    QString name;
    FieldKind kind = FieldKind::Float;
    std::function<QVariant()> get;
    std::function<void(const QVariant&)> set;   // vide = lecture seule
    double min = -1e9, max = 1e9, step = 1.0;
    int decimals = 2;
    QStringList choices;            // Choice : liste déroulante, la valeur est l'index choisi
    bool rebuildOnChange = false;   // la modification change les champs affichés
};

struct ComponentDesc {
    QString name;
    std::function<bool(Registry&, Entity)> has;
    std::function<void(Registry&, Entity)> add;      // vide = ne peut pas être ajouté depuis l'éditeur
    std::function<void(Registry&, Entity)> remove;
    std::function<std::vector<FieldDesc>(Registry&, Entity)> fields;
};

const std::vector<ComponentDesc>& componentDescriptors();

Pour exposer un nouveau composant : ajoutez une entrée dans componentDescriptors() (component_descriptors.cpp). Aucun autre fichier de l'éditeur n'est à modifier. Le type de champ Choice affiche une liste déroulante (la valeur est l'index choisi), et rebuildOnChange redessine les champs quand la modification les change (par exemple la forme d'un Geometry).

SfmlWidget : SFML dans Qt

SfmlWidget est un QWidget qui désactive son moteur de peinture Qt (paintEngine() renvoie nullptr) pour laisser SFML dessiner dans sa surface. Il crée sa sf::RenderWindow au premier affichage et déclenche un rendu environ 60 fois par seconde avec un QTimer.

editor/src/sfml_widget.hC++
// Appelée une fois, dès que la fenêtre SFML existe (au premier affichage) : créez ici votre Game.
std::function<void(sf::RenderWindow&)> onInit;
// Appelée ~60 fois par seconde : dessinez dans la fenêtre. clear() et display() sont faits pour vous.
std::function<void(sf::RenderWindow&)> onFrame;
  • TilemapView : la vue scène (cartes et entités). Molette = zoom centré sur la souris ; clic droit ou molette + glisser = déplacer la vue ; F = cadrer la carte. Sa caméra est une EditorCamera (position, zoom de 0,05 à 8), pas un composant de la scène ni un Camera2d : elle n'est jamais sauvegardée avec la scène. Elle dessine avec le même TilemapRenderSystem et le même RenderSystem que le jeu, plus des aides : grille, contours des collisions (Ctrl+Maj+C), caméras de la scène (drawCameras), aperçu du pinceau (drawGhost). Selon l'outil : Sélection (clic, glisser, Ctrl = aligner sur la grille, gizmo rouge / vert / carré), Pinceau, Gomme, Remplir, Pipette (voir Tilemaps & tilesets), Taille (poignées).
  • SceneToolbar : la barre au-dessus de la vue, pour les outils qui agissent sur les entités (V sélection, R taille). Avec l'outil Taille, on choisit ce que les poignées agrandissent : ResizeTarget::Both (forme + collision), Geometry ou Collider2D. Les calculs sont dans shape_edit.h : boîtes englobantes dans le bon repère (la collision tourne avec l'entité mais ne change pas d'échelle, comme la physique).
  • GameView : le mode jeu. Elle crée un Game en mode embarqué (Game(fenêtreExistante)) et charge une copie de la scène (sceneSnapshot()), les cartes telles qu'elles sont dans l'éditeur (même non enregistrées), le input.cfg du projet et les systèmes réglés dans le .angproj. Elle appelle tick(dt) à chaque frame et est détruite à l'arrêt, ce qui appelle onStop des systèmes. Le clavier, la souris et la molette reçus par Qt sont traduits en événements SFML (QtSfml::toSfmlEvent) puis transmis à l'InputManager du jeu. La touche Tab est réservée au jeu.

Tilesets : la fenêtre et l'import

  • TilesetDialog : crée ou modifie un tileset (image, taille de tile, marge, espacement ; type simple / 4 bords / 16 coins ; ancre, échelle, solide, tri en Y). En autotile 4 bords, chaque clic sur une tile de la feuille lui donne un rôle (Full, Edge0…3, Corner0…3, Ring, Under). Le résultat est un Tileset enregistré en .tileset, avec des chemins relatifs au projet.
  • TilesetView : la feuille découpée en grille. Clic = une tile, glisser = un bloc (tampon), Ctrl + molette = zoom ; mode « clic » dans la fenêtre Tileset pour affecter les rôles. Placée dans un QScrollArea.
  • packTilesetImages (tileset_import.h) : assemble des images séparées en une feuille (rotations _N _E _S _W sur une ligne, rognage du vide commun) et renvoie la taille de tile, les colonnes et le décalage de rognage pour recalculer l'ancre.

Le projet ouvert est celui du .angproj (le dernier ouvert, sinon projects/rpg/rpg.angproj). Le panneau Project montre son dossier ; AV_PROJECT_DIR, défini par CMake, donne le dossier du RPG par défaut. rpg est une dépendance de l'éditeur, donc construit avec lui. Le code de jeu du RPG (rpg_project) est lié à l'éditeur : après avoir écrit un comportement, il faut recompiler (voir Code de jeu).

Paramètres du jeu : Édition → Paramètres du jeu…

La fenêtre GameSettingsDialog (non modale) édite le fichier assets/settings.cfg du projet (paths.settings du .angproj), sous forme d'un GameSettings : Plein écran, VSync, Antialiasing (désactivé, 2×, 4×, 8×, 16×), FPS max (« Illimité » = 0, ignoré avec la VSync) et un groupe Post-process : un shader .frag au choix, avec un curseur par réglage // @param qu'il déclare, et un bouton Réinitialiser. Chaque changement est enregistré tout de suite et le jeu lancé dans l'éditeur (GameView::applySettings) suit les curseurs en direct, sans recompiler le shader. Plein écran, VSync et FPS max concernent la fenêtre de rpg.exe : dans l'éditeur, la fenêtre est celle du panneau.

Input Manager : Édition → Input Manager…

La fenêtre InputSettingsDialog (non modale, une seule à la fois) liste les actions du projet et leurs liens : touches, souris, molette, manette. Chaque modification est enregistrée tout de suite dans le fichier d'actions du projet (paths.input du .angproj, assets/input.cfg par défaut ; créé à partir des actions par défaut s'il n'existe pas encore).

  • Pour chaque action : nom, type (Button ou Axis), zone morte et tableau de liens avec leur échelle.
  • KeyCaptureButton : on clique sur le bouton, puis on appuie sur la touche à enregistrer (Échap annule).
  • Quand le fichier change, le signal saved() fait appeler GameView::reloadInput() : un jeu en cours dans l'éditeur prend les nouvelles touches sans redémarrer.

Le format du fichier est décrit dans le module Input.

Outils externes et console

  • ExternalTools : ouvre des fichiers dans VS Code ou CLion (exécutables trouvés dans les emplacements usuels et le PATH, ou choisis à la main et mémorisés), ou révèle un fichier dans l'explorateur. Le double-clic sur un script du panneau Project utilise l'éditeur préféré.
  • LogCapture : installé au début de main(), il redirige les flux de sortie vers le panneau Console tout en continuant d'écrire dans la console de l'IDE. Il est utilisable depuis n'importe quel thread.
