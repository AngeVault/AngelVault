Créer un composant (côté engine)

Ajouter un composant au moteur : la structure de données, sa réflexion (reflectComponent), sa sauvegarde dans les scènes, son affichage dans l'Inspector de l'éditeur et ses tests. Le pendant « données » de la page sur les systèmes.

Un composant, quatre branchements

Un composant est une simple structure de données posée sur des entités. Côté moteur, il faut ensuite le « présenter » à trois endroits qui ne connaissent pas son type : la réflexion, la sauvegarde et l'éditeur. Dans un projet, REGISTER_COMPONENT fait tout d'un coup ; dans le moteur, on le fait à la main, une fois par endroit :

#ÉtapeFichierSans elle…
1La structureengine/<module>/include/components/mon_composant.hrien n'existe
2La réflexion : reflectComponent<T>le même en-têteni sauvegarde automatique, ni liste de champs
3La sauvegarde (SerializerRegistry)engine/scene/src/component_serializers.cpple composant disparaît à l'enregistrement de la scène
4L'Inspector (ComponentDesc)editor/src/component_descriptors.cppinvisible dans l'éditeur, impossible à ajouter ou à régler

Le composant fictif de cette page est Lifetime, celui qui alimente LifetimeSystem (voir Créer un système (côté engine)). Pour un cas réel complet, suivez en parallèle CameraShake (champs simples) et CameraFollow (lien vers une autre entité).

Étape 1 : la structure

Un en-tête par composant, dans include/components/ du module qui le possède (Core pour les composants de base, Render2D pour la caméra…). Une struct avec des valeurs par défaut sensées :

engine/core/include/components/lifetime.hC++
#pragma once
// Durée de vie : l'entité est détruite quand `remaining` atteint 0 (LifetimeSystem).
#include "ecs/reflect.h"

struct Lifetime {
    float remaining = 5.f;   // secondes avant destruction
    bool  fade = false;      // (pour le rendu) s'estomper pendant la dernière seconde
};
  • Des données, pas de logique. Quelques petites méthodes utilitaires sont acceptables (CameraShake::add(amount), CameraFollow::setTarget) ; la logique d'ensemble va dans un système.
  • Une valeur par défaut à chaque champ : le composant est créé sans arguments par registry.addComponent<T>(e) et par l'éditeur.
  • Séparez réglage et état. CameraFollow a des champs réglables (smoothTime, deadZone…) et des champs d'état (velocity, started). Seuls les premiers sont réfléchis : l'état ne doit pas être sauvegardé.
  • Un lien vers une autre entité se déclare Entity target = NULL_ENTITY;. Jamais Entity{} : c'est l'entité d'index 0.

Étape 2 : la réflexion

reflectComponent<T> renvoie la liste des champs réglables, avec un pointeur vers chacun. C'est ce que lisent la sauvegarde générique et les outils qui ne connaissent pas le type. Une spécialisation de fonction, dans le même en-tête, juste sous la structure :

engine/core/include/components/lifetime.hC++
template<>
inline ReflectedComponent reflectComponent<Lifetime>(Lifetime& c) {
    return { "Lifetime", {
        { "remaining", PropertyInfo::Type::Float, &c.remaining },
        { "fade",      PropertyInfo::Type::Bool,  &c.fade      },
    } };
}
PropertyInfo::TypeType C++
Floatfloat
Intint
Boolbool
Vec2fsf::Vector2f
Stringstd::string

Le nom compte. La chaîne de { "remaining", … } est la clé écrite dans le fichier .scene. La renommer casse les scènes existantes (la valeur est ignorée au chargement, sans erreur). Ne réfléchissez ni les couleurs, ni les énumérations, ni les Entity : ces types ne sont pas dans PropertyInfo ; ils passent par un serializer écrit à la main (étape 3, variante B).

ComponentRegistry::registerComponent<T>() existe aussi (il sert à reflectEntity), mais il n'est appelé nulle part aujourd'hui : l'éditeur passe par ses propres ComponentDesc (étape 4). Vous n'avez rien à y ajouter.

Étape 3 : la sauvegarde

Le SerializerRegistry associe un nom de composant à une fonction « écrire en JSON » et une fonction « relire ». Les composants du moteur sont enregistrés dans registerBuiltins, dans engine/scene/src/component_serializers.cpp. Deux cas.

A. Tous les champs réfléchis suffisent : addReflected

engine/scene/src/component_serializers.cppC++
#include "components/lifetime.h"        // avec les autres #include du fichier

// ... dans registerBuiltins(SerializerRegistry& reg) :
reg.addReflected<Lifetime>("Lifetime");
reg.addReflected<CameraShake>("CameraShake");   // un exemple existant

Une ligne. Tous les champs de reflectComponent sont écrits dans un objet JSON ; au chargement, les clés absentes gardent leur valeur par défaut. Les anciennes scènes sans le composant continuent donc de se charger, et une nouvelle clé dans un composant existant n'invalide aucun fichier.

B. Le composant contient une Entity : add avec deux fonctions

Un index d'entité n'a aucun sens d'une session à l'autre (cases recyclées, ordre de création). Les liens passent par le PersistentId : ctx.idOf(entité) à l'écriture, ctx.entityOf(id) à la lecture. Voici le vrai code de CameraFollow :

engine/scene/src/component_serializers.cppC++
reg.add<CameraFollow>("CameraFollow",
    [](CameraFollow& c, const SaveContext& ctx) {          // sauvegarde
        Json j = Json::object();
        const uint64_t target = ctx.idOf ? ctx.idOf(c.target) : 0;
        j["target"] = target ? Json(target) : Json(nullptr);   // 0 = aucune entité
        for (const PropertyInfo& p : reflectComponent<CameraFollow>(c).fields) j[p.name] = property(p);
        return j;
    },
    [](CameraFollow& c, const Json& j, const LoadContext& ctx) {   // chargement
        for (PropertyInfo& p : reflectComponent<CameraFollow>(c).fields)
            if (j.contains(p.name)) readProperty(j[p.name], p);
        c.setTarget(entityRef(j, "target", ctx, "CameraFollow"));  // PersistentId -> Entity (avec un avertissement si introuvable)
    });

Les aides de l'espace de noms SceneJson (property, readProperty, value<T>(j, "clé", défaut), color(...)) évitent d'écrire le JSON à la main ; Json est un nlohmann::ordered_json (l'ordre des clés est conservé : les fichiers restent lisibles et se comparent bien dans git).

Le serializer sait aussi migrer. Quand la caméra a été découpée en Camera2d + CameraFollow + CameraBounds + CameraControl, le chargement de Camera2d a gagné une fonction migrateOldCamera : un ancien fichier recrée les nouveaux composants. Si vous changez la forme d'un composant existant, faites de même dans sa fonction de chargement plutôt que de casser les scènes.

Étape 4 : l'Inspector de l'éditeur

L'Inspector (Qt) n'utilise pas reflectComponent : il a une description à lui, ComponentDesc, qui sait tester, ajouter, retirer le composant et construire la liste de ses champs avec un getter et un setter pour chacun (ça marche donc aussi pour des champs privés ou des variantes). On ajoute un bloc dans build(), dans editor/src/component_descriptors.cpp, à côté des autres :

editor/src/component_descriptors.cppC++
#include "components/lifetime.h"        // avec les autres #include du fichier

// ... dans build(), avant « return list; » :
{
    ComponentDesc d{ "Lifetime" };
    d.has    = [](Registry& r, Entity e) { return r.hasComponent<Lifetime>(e); };
    d.add    = [](Registry& r, Entity e) { r.addComponent<Lifetime>(e); };      // vide = « pas ajoutable depuis l'éditeur »
    d.remove = [](Registry& r, Entity e) { r.removeComponent<Lifetime>(e); };
    d.fields = [](Registry& r, Entity e) {
        using C = Lifetime;
        std::vector<FieldDesc> f;
        f.push_back(floatRef<C>(r, e, QObject::tr("Durée restante (s)"), [](C& c) -> float& { return c.remaining; }, 0, 3600, 0.5));
        f.push_back(boolRef<C>(r, e, QObject::tr("S'estomper"), [](C& c) -> bool& { return c.fade; }));
        return f;
    };
    list.push_back(d);
}

Les aides déjà écrites dans ce fichier couvrent les types usuels :

AideChampParamètres utiles
floatRef<C>nombre décimalmin, max, step
intRef<C>entier
boolRef<C>case à cocherreadOnly
vecRef<C>sf::Vector2f (deux cases X / Y)step
colorRef<C>sf::Color (sélecteur)
stringRef<C>texte
label(nom, texte)texte en lecture seulepour une Entity : afficher le nom de la cible (voir CameraFollow)
FieldDesc Choiceliste déroulante (valeur = index)choices, rebuildOnChange si le choix change les champs affichés (forme de Geometry)
  • Le QObject::tr(…) rend les libellés traduisibles. Le texte est celui que voit l'utilisateur ; le nom du composant (ComponentDesc d{ "Lifetime" }) est celui du menu Ajouter un composant.
  • Si votre composant exige un autre composant (CameraFollow a besoin d'un Transform2D), faites-le dans d.add : withTransform(r, e); r.addComponent<CameraFollow>(e);.
  • Un champ en lecture seule se fait en laissant set vide, ou avec boolRef(..., true).
  • L'éditeur met à jour l'Inspector depuis les getters : il reflète donc aussi les changements faits pendant l'exécution (F5), par exemple un remaining qui descend.

Étape 5 : tester

Pour la structure et la réflexion, un test sans éditeur ni fenêtre suffit ; pour la sauvegarde, tests/test_scene.cpp montre comment écrire une scène puis la relire. Un test de réflexion :

tests/test_lifetime.cppC++
#include "components/lifetime.h"
#include "ecs/registry.h"
#include <cstdio>

static int g_failures = 0;
#define CHECK(cond) do { if (!(cond)) { std::printf("ECHEC ligne %d : %s\n", __LINE__, #cond); ++g_failures; } } while (0)

int main() {
    Registry r;
    const Entity e = r.createEntity();
    r.addComponent<Lifetime>(e);

    ReflectedComponent info = reflectComponent<Lifetime>(r.getComponent<Lifetime>(e));
    CHECK(info.name == "Lifetime");
    CHECK(info.fields.size() == 2);
    CHECK(info.fields[0].name == "remaining");
    info.fields[0].as<float>() = 2.f;                        // écrit dans le composant
    CHECK(r.getComponent<Lifetime>(e).remaining == 2.f);

    return g_failures == 0 ? 0 : 1;
}

Même CMakeLists.txt que pour un système (add_executable + target_link_libraries(… AngeVault::Core) + add_test). Un champ qui n'est pas dans reflectComponent n'est pas sauvegardé : ce test attrape l'oubli le plus courant.

Liste de contrôle

  • □ include/components/mon_composant.h : struct, valeurs par défaut, état séparé du réglage.
  • □ reflectComponent<T> dans le même en-tête, noms de champs stables.
  • □ registerBuiltins : addReflected<T>("Nom"), ou add<T> avec idOf / entityOf pour les liens entre entités.
  • □ component_descriptors.cpp : un bloc ComponentDesc avec has, add, remove, fields.
  • □ Le module du composant est une dépendance de Scene (av_module(Scene DEPS …) dans engine/scene/CMakeLists.txt). L'éditeur lie AngeVault::Engine : il voit déjà tous les modules.
  • □ Un système l'utilise (ou un comportement) : Créer un système (côté engine).
  • □ Test dans tests/, puis dans l'éditeur : ajouter, régler, enregistrer, rouvrir la scène.
  • □ Documenté dans Référence des composants.

Le plus fréquent : oublier une étape. Sans l'étape 3, le composant semble fonctionner puis disparaît à la sauvegarde. Sans l'étape 4, il marche en jeu mais reste invisible dans l'éditeur. Sans l'étape 2, ni l'une ni l'autre ne compile ou ne fonctionne.
